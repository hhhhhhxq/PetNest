# PetNest 按页面同步资源设计

## 目标

精简托盘菜单，并让远程资源在用户进入实际使用它们的设置页面时自动完成检查和获取。整个流程不得阻塞设置窗口，不得中断现有资源的使用，也不要求用户再次确认下载。

## 已确认的交互

- 从托盘菜单移除“鼠标样式…”；鼠标主题只从“设置…”中的“鼠标与行为”管理。
- 从托盘菜单移除“立即检查资源更新”；资源检查和下载不再需要手动入口。
- 用户打开或切换到“鼠标与行为”或“工作倒计时”时，触发一次受 24 小时状态节流保护的异步资源检查。
- 如果持久化状态已经标记有更新，则跳过重复检查并直接在后台下载；如果本次检查发现更新，也立即开始后台下载。
- 检查、下载和资源校验均在现有后台工作线程中运行。并发进入其它相关页面时复用正在进行的任务，不启动第二个任务。
- 检查或下载期间继续显示和使用当前缓存或安装包内置资源；单个新资源完整校验后才原子切换。

## 页面状态

设置中心内容标题下方提供一个共享的轻量状态区域，只在“鼠标与行为”和“工作倒计时”页面显示：

- 检查中：`正在获取最新资源信息…`
- 下载中：`正在下载新资源… 43%`
- 全部完成：`新资源已就绪`，短暂停留后自动隐藏。
- 无更新：安静结束，不显示完成提示。
- 检查或下载失败：`新资源获取失败，将稍后自动重试`。失败状态不弹窗、不阻塞设置操作，并在离开页面后隐藏。

下载完成后刷新运行时资源目录。若设置中心仍然打开，鼠标主题下拉框同步刷新，同时保留用户在窗口内尚未保存的当前选择；倒计时窗口重新加载背景目录，但不强制替换正在显示的背景。互动动效继续随同一份全局资源清单下载，并在下次打开互动窗口时使用新目录。

## 调度与数据流

1. 设置中心报告当前选中的 section key。
2. 应用层只对 `mouse_behavior` 和 `countdown` 调用上下文资源同步入口。
3. 同步入口先检查是否已有资源工作线程：有则只把页面状态与现有任务同步；没有则根据持久化的 `update_available` 决定直接应用，或调用受节流的 manifest 检查。
4. 检查结果通过现有结果队列回到 GUI 线程。发现更新时自动进入 apply；无更新时清空页面状态；错误时显示非阻塞错误状态。
5. apply 的进度和结果继续通过结果队列回到 GUI 线程，刷新目录及页面选项。

应用启动时不再主动检查资源，也不再启动每 30 分钟的资源检查计时器。结果轮询计时器保留，因为网络和文件工作仍由后台线程完成。应用安装包更新的启动检查和“应用与更新”页面行为不在本次范围内。

## 方案取舍

考虑过以下方案：

1. 保留启动/周期检查，只把下载改为页面触发。优点是页面打开前可能已知道有更新，缺点是仍会在用户不使用相关页面时产生网络请求。
2. **采用：相关页面触发全局检查并自动下载。** 与用户操作语境一致，沿用现有全局 manifest、原子缓存和单工作线程，改动边界最清晰。
3. 每个页面只检查和下载对应资源类型。网络量可能更小，但需要拆分 manifest 状态、缓存切换和失败重试语义；当前资源体量与需求不值得引入这层复杂度。

## 错误和边界处理

- manifest 获取失败、格式错误、文件大小或 SHA-256 校验失败时保留旧资源。
- 部分资源成功时立即刷新成功资源；失败资源继续使用旧版本，并显示统一失败状态，之后再次进入相关页面时按现有 update 状态重试。
- 设置窗口在任务过程中关闭时，后台任务继续安全完成；结果只更新仍存在的窗口和运行时目录。
- 应用退出时不启动新任务，已有守护线程不阻塞退出。
- 当前已经应用到系统的鼠标主题不因目录刷新而被强制切换；用户应用设置或下次启动时才使用新文件。

## 测试标准

- 托盘菜单不再创建或暴露鼠标样式和资源更新动作，其他动作顺序与行为保持正常。
- 进入两个资源相关 section 会请求上下文同步；进入其它 section 不会。
- 已有更新时直接下载；检查发现更新时自动下载；无更新时不下载。
- 检查、下载、进度、完成和失败状态使用确认后的文案并保持非阻塞。
- 下载完成后打开中的鼠标主题列表刷新且保留当前选择。
- 启动过程不再发起资源检查或启动周期检查计时器。
- 相关单元测试、托盘测试、设置中心测试和应用集成测试通过。
