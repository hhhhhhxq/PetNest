# Windows 公用网络局域网防火墙提醒设计

## 背景

PetNest 的局域网发现、互动、预警池名单同步和 Codex 用量同步使用 UDP `18487`，聊天和部分名单帧使用 TCP `18487`。Windows 安装器当前总会创建绑定安装目录 `PetNest.exe` 的两条入站规则，默认仅适用于专用网络；只有用户在安装时勾选“允许在公用网络中使用局域网互动”，规则才同时适用于公用网络。

部分公司网络会被 Windows 分类为公用网络。用户容易忽略安装页中的可选项，结果是设备可以主动广播自身，却无法稳定接收握手、名单同步或聊天连接。单纯把安装选项默认勾选会让移动电脑以后在咖啡店、酒店等公用网络中无提示开放 PetNest 端口，因此需要在真正使用局域网功能时提供醒目但不打断工作的运行时提醒。

macOS 没有 Windows 的专用/公用网络防火墙配置文件语义，并使用系统级按应用授权提示，因此本设计只改变 Windows 行为。

## 目标

- 当 Windows 当前活动网络属于公用网络、局域网互动已启用且 PetNest 公用网络入站规则不完整时，主动提醒用户。
- 提醒不抢焦点、不阻塞桌宠或其他应用，也不自动消失。
- 用户可以从互动窗口一键申请管理员权限，修复绑定当前 `PetNest.exe` 的 UDP/TCP `18487` 规则。
- 用户明确关闭提醒后，在同一个公用网络中不再主动弹出；切换到另一个公用网络时重新提醒。
- 无论主动气泡是否被关闭，互动窗口都持续展示防火墙状态和修复入口，直到规则完整。
- 保持安装器当前“专用网络默认放行、公用网络默认不放行”的安全默认值。

## 非目标

- 不关闭 Windows 防火墙。
- 不创建对所有程序或所有端口生效的规则。
- 不改变 macOS 防火墙设置或模拟 Windows 公用网络提示。
- 不解决 VLAN 路由、无线客户端隔离、远端设备离线或第三方安全软件拦截。
- 不增加跨网段消息中继；修复后仍要求网络路由允许设备直连。
- 不把安装器的公用网络选项改为默认勾选。

## 当前行为保持不变

安装器继续请求管理员权限，并在安装完成后删除同名旧规则，再为当前安装路径创建：

- `PetNest LAN UDP 18487`
- `PetNest LAN TCP 18487`

未勾选公用网络选项时，两条规则使用 `profile=private`；勾选后使用 `profile=private,public`。卸载时继续删除这两条规则。

## 用户体验

### 触发条件

只有同时满足下列条件时才显示主动提醒：

1. 当前平台是 Windows。
2. `lan_interaction_enabled` 为 `true`。
3. 至少一个当前活动且可联网的 Windows 网络配置文件属于公用网络。
4. UDP 或 TCP `18487` 公用网络入站规则缺失、禁用、绑定了旧程序路径或不允许入站。
5. 用户尚未对当前公用网络关闭过主动提醒。

应用完成启动后延迟约 5 秒执行首次检查，避免启动过程中的短暂网络状态和界面竞争。之后在以下时机重新检查：

- 用户开启局域网互动；
- 用户打开互动窗口；
- Windows 报告网络连接状态发生变化；
- 用户完成或取消防火墙修复。

网络变化事件需要做短延迟合并，避免一次切换触发多个检查。正常运行期间不通过高频启动 PowerShell 轮询网络状态。

### 宠物旁常驻气泡

首次发现问题时，在桌宠旁显示独立的防火墙提醒气泡：

> 当前公用网络可能阻止局域网互动，点击检查

行为规则：

- 气泡不抢键盘焦点，不阻塞鼠标或其他窗口。
- 气泡没有自动消失计时器。
- 点击正文：打开互动窗口，然后关闭气泡。
- 点击右上角关闭按钮：关闭气泡，不打开互动窗口。
- 关闭后记录当前公用网络的稳定标识；只要仍是同一个网络，就不再主动显示。
- 切换到另一个公用网络且规则仍不完整时，显示新的提醒。
- 局域网功能关闭、规则修复或不再处于公用网络时，立即隐藏气泡。

防火墙提醒使用独立组件和状态，不复用远程互动消息气泡，避免两类消息互相覆盖或清除。

### 互动窗口警告条

互动窗口顶部新增持久橙色警告条：

> 公用网络防火墙尚未放行，部分设备可能无法连接　[一键允许]

警告条由实时防火墙状态控制，不受“关闭主动气泡”的记忆影响。只要触发条件中的规则问题仍存在，每次打开互动窗口都显示。

点击“一键允许”前不请求管理员权限。按钮进入处理中状态，防止重复点击。

### 管理员授权与结果

点击“一键允许”后，PetNest 通过 Windows `runas` 仅启动一次受限的提权辅助流程。辅助流程使用固定命令参数，删除两条 PetNest 同名规则，并重新创建同时适用于 `private,public` 的规则：

- 程序必须是当前正在运行的 `PetNest.exe` 绝对路径；
- UDP 规则只允许本地端口 `18487`；
- TCP 规则只允许本地端口 `18487`；
- 两条规则均为入站允许且启用；
- 不经过拼接的 shell 命令执行用户可控文本。

父进程等待辅助流程结束，但不得阻塞 Qt 界面线程。结束后重新读取实际规则，不能只依据子进程退出码宣称成功。

- 两条规则均验证成功：隐藏气泡和警告条，显示“局域网互动已放行”，立即执行一次局域网发现和已保存伙伴探测。
- 用户取消 UAC：显示“未修改防火墙设置”，警告条保留，按钮恢复可用。
- 执行失败或仅一条规则成功：显示可重试的错误信息，警告条保留；不得把部分成功当作完成。
- 企业策略禁止本地防火墙规则：说明“此设备由组织策略管理，请联系管理员放行 PetNest UDP/TCP 18487”，不循环弹出 UAC。

## 网络与规则检测

新增 Windows 专用的防火墙状态服务，向应用层返回结构化结果，而不是让 UI 解析命令行文本。状态至少包含：

- 当前是否存在活动公用网络；
- 当前公用网络的稳定标识；
- UDP 规则是否完整；
- TCP 规则是否完整；
- 是否受组织策略限制；
- 检测失败的用户可读原因。

Windows 查询结果必须使用机器可读格式，避免解析本地化的 `netsh` 展示文本。网络标识只用于本机关闭记忆；持久化时保存不可逆摘要，不保存 Wi-Fi 名称、SSID 或其他可识别网络名称。

如果检测本身失败，不主动显示“公用网络未放行”的确定性结论。互动窗口可以显示较弱的诊断提示并提供重新检查，日志记录技术原因。

## 状态持久化

设置中新增有界的“已关闭防火墙提醒网络摘要”集合：

- 只保存摘要，不保存原始网络名称。
- 最多保留最近 20 个，避免无限增长。
- 成功创建并验证公用网络规则后清空该集合，因为提醒条件已经消失。
- 设置损坏或旧版本没有该字段时按空集合处理。
- 关闭气泡只影响主动提醒，不影响互动窗口警告条。

## 组件边界

### `WindowsLanFirewallAdvisor`

负责只读检测活动网络类别、检查两条规则、生成稳定网络摘要，并协调提权辅助流程。它不创建 UI，也不决定提示文案。所有外部命令执行和 Windows API 调用都可注入，以便单元测试。

### 防火墙辅助入口

在 PetNest 可执行文件增加一个只接受固定参数的内部辅助入口。该入口必须在单实例和 GUI 初始化前处理；只执行 PetNest 防火墙规则配置，完成后返回明确退出码。普通用户输入不能控制规则名、端口、协议或目标程序路径。

### 应用协调器

负责把设置、网络状态和规则状态合并为展示状态；安排启动延迟与网络变化后的检查；控制气泡；在修复成功后触发局域网重新发现。耗时检测和提权等待均放在后台，结果回到 Qt 主线程应用。

### `LanFirewallNoticeBubble`

独立的非模态桌宠旁气泡，提供正文点击和右上角关闭信号。它不直接修改设置或防火墙。

### 互动窗口

只接收结构化状态，展示或隐藏橙色警告条，并把“一键允许”操作转发给应用协调器。

## 数据流

```text
启动／启用局域网／打开互动窗口／网络变化
  → 后台检测活动网络与防火墙规则
  → 应用协调器判断是否需要提醒
  → 未关闭过当前网络：显示常驻气泡
  → 互动窗口打开：始终按实时状态显示警告条
  → 用户点击“一键允许”
  → 一次 UAC → 提权辅助入口配置两条规则
  → 后台重新验证
  → 成功：清除提醒并重新发现设备
  → 取消或失败：保留警告条并允许重试
```

## 边界情况

- 同时存在专用和公用活动网络：只要公用网络可能承载 PetNest 流量且公用规则不完整，就显示提醒。
- VPN、虚拟网卡和无默认路由接口：不把仅内部或不可联网的接口单独视为触发条件。
- 安装目录变化：旧程序路径的规则视为不完整，一键修复绑定当前可执行文件。
- UDP、TCP 只有一条规则有效：视为未完成，明确指出缺少的协议。
- PetNest 未冻结运行（开发环境）：不提供一键提权修改真实防火墙，只显示开发诊断状态，避免给 Python 解释器创建宽泛规则。
- 用户关闭局域网互动：停止主动检查并隐藏相关提示，不删除已有规则。
- 规则被管理员或安全软件再次删除：下次触发检查时重新显示警告。
- Windows 防火墙整体关闭：不要求创建公用规则；显示为无需处理，但日志可记录防火墙关闭状态。
- 旧版设置文件：自动使用默认空关闭集合，不迁移无关字段。
- macOS 和其他平台：不创建 Windows 提示、规则或设置记录。

## 安全要求

- 保持安装器公用网络选项默认关闭。
- 规则限定当前 `PetNest.exe`、入站方向、UDP/TCP `18487`。
- 不允许任意程序路径、端口、规则名或附加参数进入提权辅助入口。
- 不记录 SSID、网络名称或完整命令中的隐私数据。
- UAC 取消是正常用户选择，不作为崩溃或自动重试条件。
- 公用网络规则只改善连通性，不改变局域网协议仍以可信网络为前提的安全说明。

## 测试策略

### 状态检测

- 非 Windows、局域网关闭、仅专用网络、公用网络且规则完整、公用网络且规则缺失。
- UDP/TCP 单边缺失、规则禁用、程序路径失配、动作不是允许。
- 多活动网络、VPN/虚拟接口、检测命令失败和组织策略限制。

### 提醒状态

- 气泡不会随时间自动消失。
- 点击正文打开互动窗口并关闭气泡。
- 点击关闭按钮不打开窗口，并记录当前网络摘要。
- 同一网络不再主动显示；新公用网络重新显示。
- 关闭气泡后互动窗口警告条仍存在。
- 局域网关闭、网络变为专用或规则修复后气泡立即隐藏。

### 提权流程

- 只发起一次 UAC，固定配置 UDP/TCP `18487`。
- 成功后必须经过实际规则复查才清除警告，并触发重新发现。
- UAC 取消、执行失败、部分成功和策略阻止都保持可恢复状态。
- 开发环境拒绝为 Python 解释器创建规则。

### 回归

- 安装器继续默认创建仅专用网络规则，勾选后创建专用加公用规则。
- 卸载仍删除两条规则。
- 局域网服务、已保存伙伴重连、预警池名单同步、聊天和测试环境广播隔离不回归。
- macOS 启动和局域网功能不出现 Windows 防火墙提示。

## 验收标准

- 公用网络规则缺失时，Windows 用户能够看到不会自动消失的宠物旁提醒。
- 提醒正文和关闭按钮行为符合约定，关闭记忆按网络生效。
- 互动窗口在问题存在期间始终提供清晰的一键修复入口。
- 一次 UAC 后同时配置并验证 UDP/TCP `18487`，失败时不误报成功。
- 专用网络、已正确放行、公用网络以外平台以及局域网功能关闭时不打扰用户。
- 安装器现有安全默认值保持不变。
