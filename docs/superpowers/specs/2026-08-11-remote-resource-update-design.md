# PetNest 远程资源更新设计

## 目标

让 PetNest 在不更新安装包的情况下发现并使用私有 GitHub 资源仓库中的光标、互动动效和倒计时背景，同时保证启动不被网络阻塞、更新失败不破坏现有资源。

## 更新触发

客户端保存资源状态，不把资源状态混入用户偏好设置：

- 启动后提交一次后台检查任务；只有距离 `last_check_at` 至少 24 小时，或本地没有成功检查记录时，才请求 Worker manifest。
- 程序运行期间由 30 分钟 QTimer 触发同一个“是否到期”判断，因此不会重复请求。
- 托盘菜单的“立即检查资源更新”绕过 24 小时限制，立即请求 manifest。
- 检查只读取并校验 manifest，不在启动线程下载 800 多个动效帧。

发现远程 catalog 或文件 SHA-256 与当前应用版本不同时，持久化 `update_available=true`，托盘菜单动作显示蓝色图标。自动检查只更新提示状态；用户点击动作后才下载资源。下载完成后，未正在使用的资源立即可用并清除蓝点；正在显示的倒计时皮肤延迟到下一次显示，当前系统光标路径保持不变。

## 缓存与原子切换

缓存目录位于用户可写目录 `%APPDATA%/PetNest/remote-resources`（其他平台使用对应应用数据目录）：

```text
remote-resources/
├─ versions/<catalog>-<digest>/resources/...  # 每次资源成功后的不可变混合视图
├─ current.json
├─ state.json
└─ staging/<run-id>/...
```

下载流程按 manifest 中的单个资源（一个光标主题、一个特效或一个倒计时背景）分别创建临时文件集，逐文件核对大小和 SHA-256。一个资源的全部文件验证成功后，复制/链接到新的不可变混合视图，再用临时文件原子替换 `current.json` 指针；应用收到每次切换回调后立即刷新未正在使用的资源，因此后续资源即使继续下载或失败也不会回滚它。失败资源保留上一代资源，首次安装则继续使用安装包内置默认值。资源内部仍不会出现半套文件。

当当前正在使用光标主题或正在显示倒计时卡片时，不修改其已打开的路径；新光标在下一次选择/启动时生效，新倒计时皮肤在卡片隐藏后生效。光标、特效和倒计时背景之间没有业务耦合，允许它们处于不同版本；只要求同一资源包内部保持一致。

## 应用集成

- `RemoteResourceCache` 提供 manifest 获取、版本化下载、校验、回退和安全路径解析。
- `RemoteResourceUpdateCoordinator` 管理检查节流、状态文件、蓝点状态和手动应用更新。
- 应用启动后创建协调器并提交后台任务；网络异常只记录日志并继续使用 current 或安装包内置资源。
- `CursorStyleCatalog` 优先扫描 current 版本的 `resources/cursors`；current 视图会保留未成功远程更新的安装包默认资源，因此不会因另一个主题更新成功而丢失默认主题。
- 倒计时背景和互动动效同样使用带默认资源 overlay 的 current 视图；本次不改变它们已有的播放逻辑。
- 托盘增加“立即检查资源更新”动作，使用蓝色图标表示更新待处理，不改变现有菜单动作接口。
- 文件 URL 带资源 SHA-256 查询参数；Worker 只允许 manifest 白名单中的路径和匹配 SHA，并只对这些资源 URL 做长期边缘缓存。manifest 响应始终 `no-store`，Worker 内的白名单只短暂缓存（最多 10 秒），因此手动检查不会被长期边缘缓存的旧 manifest 延迟。

## 错误处理

- Worker、JSON、路径、文件大小或 SHA-256 任一校验失败：只丢弃失败资源的 staging，保留该资源旧版本；同批已成功的其它资源继续生效。
- 首次冷缓存只有归档接口明确返回 404 时才回退逐文件下载；502/503 或归档校验失败不会放大为大量 GitHub API 请求。
- 没有历史缓存：使用安装包资源；失败资源的蓝点状态保持待处理并允许重试。
- 手动下载部分成功：刷新已成功资源、保留蓝点，并提示成功/失败资源；全部成功后才清除蓝点。
- 状态文件损坏：丢弃状态并按首次启动处理，不影响用户设置文件。

## 验证标准

- 单元测试覆盖 24 小时节流、手动绕过、蓝点持久化、完整 staging 失败回退和版本指针原子切换。
- 现有项目测试全部通过。
- 使用线上 Worker manifest 验证至少一个光标、一个动效和一个倒计时背景的大小与 SHA-256。
