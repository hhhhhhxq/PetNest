# 正在使用的宠物动作安全更新设计

## 背景

当前动作导入通过复制完整宠物包并交换整个宠物目录来提交修改。Windows 会在目录或其文件被占用时拒绝目录改名；更严重的是，现有异常处理会在第一次改名失败后误删仍位于原路径的宠物目录。

动作导入只修改选中的动作资源、`pet.json` 中对应的动作定义，以及用户明确选择导入的绑定。它不应替换整个宠物目录。

## 目标

- 支持为当前正在运行的宠物新增或替换动作。
- 提交过程中不改名、删除或整体替换宠物根目录。
- 不覆盖运行时可能仍在读取的旧动作文件。
- 提交前失败时保持原配置和原资源不变。
- 配置切换后重新加载失败时恢复旧配置，继续使用旧动作。
- 修复通用目录事务在第一次改名失败时误删原目录的问题。

## 非目标

- 不改变完整宠物包导入的用户流程。
- 不在本次修复中重构宠物包格式或动画播放器。
- 不保证旧资源在更新完成的同一时刻立即删除；安全性优先于即时清理。

## 方案

### 1. 通用目录事务止损

`PackageTransaction` 必须显式记录原目录是否已经成功移动。只有原目录确实移动到备份路径后，异常处理才能删除候选目标并恢复备份。

如果第一次 `target.rename(backup)` 失败：

- 原目录保持原样；
- 候选目录由上下文退出逻辑清理；
- 错误信息说明提交失败且原目录未改动；
- 不调用 `rmtree(target)`。

如果原目录已移动、候选目录提交失败：

- 只删除已提交到目标路径的候选目录；
- 将真实存在的备份目录恢复为原路径；
- 如果恢复也失败，错误信息必须包含备份路径，不得声称已经恢复。

### 2. 动作资源使用不可变修订目录

每次导入把选中动作复制到宠物目录下的新修订目录：

```text
animations/.revisions/<安全动作名>-<随机标识>/
```

新目录写完后不再原地修改。当前运行时继续引用旧动作目录，因此 Windows 文件占用不会阻止新资源落盘。

动作定义中的 `path` 改为对应修订目录。动作的对外名称、绑定和回退名称保持不变。

### 3. 以 pet.json 作为唯一提交点

导入器在内存中生成合并后的配置，并用候选配置验证整个宠物包。验证成功后：

1. 保存旧 `pet.json` 字节作为进程内回滚数据；
2. 在同目录写入临时配置并刷新到磁盘；
3. 使用 `os.replace()` 原子替换 `pet.json`；
4. 返回安装结果，由应用层重新发现并加载目标宠物。

配置替换前的任何失败只需删除本次新建的修订目录。配置替换后的应用层重新加载失败时，应用层调用安装结果提供的回滚操作恢复旧配置，再重新加载旧宠物。

### 4. 旧资源清理

重新加载成功前不得删除旧动作目录。重新加载成功后，只清理本次被替换且已不再被新配置引用的旧动作目录。

清理是尽力而为的：Windows 仍占用旧文件时保留旧目录，不回滚已经成功的动作更新。后续启动或后续导入可以再次清理未被 `pet.json` 引用的修订目录。

清理范围必须限制在宠物根目录内，拒绝绝对路径、盘符路径、符号链接和目录逃逸。

### 5. 应用层行为

更新当前宠物时：

- 允许导入操作继续执行；
- 旧动画在提交期间继续播放；
- 配置提交后立即重新发现宠物包并重载当前宠物；
- 重载成功后刷新宠物与动作中心，并尝试清理旧资源；
- 重载失败则恢复旧配置并重载旧宠物，界面显示明确失败原因。

更新非当前宠物时不触发当前宠物重载，只刷新包列表。

### 6. 错误处理

- 新资源复制或校验失败：删除本次修订目录，原配置不变。
- `pet.json` 原子替换失败：删除本次修订目录，原配置不变。
- 当前宠物重载失败：恢复旧 `pet.json`；旧资源尚未删除，因此可继续加载。
- 旧资源清理失败：记录警告，不把成功更新改判为失败。
- 回滚配置失败：保留旧配置备份路径并展示可操作错误，不声称恢复成功。

## 测试

### 通用目录事务

- 第一次原目录改名抛出 `PermissionError` 时，原目录及全部内容保持不变。
- 原目录已成功备份、候选目录提交失败时，原目录从备份完整恢复。
- 恢复失败时错误包含真实备份路径，且不显示“已恢复”。

### 动作安装

- 为当前宠物新增动作时不调用宠物根目录的 `rename` 或 `rmtree`。
- 替换动作时，新配置指向新的修订目录，旧目录在提交完成前保持存在。
- 资源复制、候选校验或配置替换失败时，原 `pet.json` 和旧动作资源字节不变。
- 导入绑定和动作重命名继续保持现有行为。
- 路径逃逸、符号链接及不安全动作名继续被拒绝。

### 应用集成

- 更新当前宠物后重新加载成功，并在成功后才清理旧资源。
- 重新加载失败时恢复旧配置并重新加载旧宠物。
- 更新非当前宠物不打断当前动画。

## 验收标准

- 运行中的 `pingan` 可以导入动作包，无需关闭 PetNest 或切换宠物。
- 导入过程中不交换或删除 `pets/pingan`。
- 任一受控失败点都不会造成宠物包丢失或旧动作丢失。
- 现有动作导入、完整宠物导入、动作导出和宠物重载测试保持通过。
