# 互动道具拖拽视觉设计

## 状态

设计于 2026-08-31 确认。本次只优化互动道具入口与道具盘的视觉可读性和拖拽暗示，不改变 `interaction.item.<id>` 事件协议、宠物包格式或动作绑定。

## 问题

当前入口位于独立无边框工具窗口中，但窗口没有启用真正的透明背景，Windows 会把控件外的透明区域显示成黑色方块。入口按钮自身又使用常驻白色圆角矩形，使它更像普通按钮。

道具盘中的每个道具也使用相同的 `QToolButton` 圆角按钮样式。用户第一眼会预期单击，而不是把它看成可以从盒子里拿出并拖给宠物的物体。现有拖拽行为已经可用，缺少的是操作暗示与抓取反馈。

## 目标

- 入口常态只显示盒子图形，不显示黑边或常驻圆角矩形底板。
- 盒子图形在明暗和复杂桌面背景上仍然可辨识，并保留足够大的点击区域。
- 道具盘看起来像打开的轻量托盘，道具看起来像可以拿起的物体，而不是一组点击按钮。
- 用户从悬停、按下到拖动的每个阶段都获得一致的抓取反馈。
- 首次打开时用一次短提示建立“拖给宠物”的操作模型，后续不持续打扰。
- 保持键盘焦点策略、无激活窗口行为、屏幕边界定位和现有状态机不变。

## 不在本次范围

- 单击道具直接触发动作。
- 点击道具后进入跨窗口的“拿起”模式。
- 用户可配置的道具盘主题、教学开关或教学持久化设置。
- 修改宠物资源、道具图标或动作绑定。

## 入口样式

`InteractionItemToolbox` 顶层窗口启用 `WA_TranslucentBackground`，根框架保持透明，从根因消除黑色窗口底色。

入口保留约 40–44 px 的透明命中区域，但常态背景和边框都透明，只显示橙色 `package-open` 图形。盒子图形使用独立的填充层和描边层：先画完整暖橙填充，再把盒盖、折线和外轮廓全部绘制到最上层，避免重叠填充遮掉结构线。图形尺寸使用 25 px，带轻微中性投影以适应浅色、深色和复杂桌面背景。悬停、按下或道具盘展开时才显示低不透明度的圆形暖色光晕；不再出现常驻白色圆角矩形。

入口继续使用“互动道具”工具提示和无焦点策略，不增加文字标签。

## 道具盘样式

展开区域使用轻量的自然白橡木置物架视觉，不再只是一块白色圆角面板。透明 PNG 资产提供细木纹、哑光木蜡油、薄倒角层板、低后沿和紧凑端盖；运行时采用端盖保护的横向三段拉伸，只缩放均匀中段，适配一至四列而不压扁木作端头。标题“拖给宠物”悬浮在道具上方。

道具不再继承入口按钮的统一圆角按钮样式。每个道具占据稳定的透明命中区域，图标下方显示简短名称；常态没有按钮边框、按下凹陷或高对比度底板。每个图标在箱底上方保留椭圆接触阴影，常态上抬约 2 px；悬停时图标再上升约 4 px并轻微放大，同时阴影拉开。拖动时隐藏图标但保留接触阴影和淡槽位，表现物体已经从纸箱中被拿起。

最多八个道具和四列布局规则保持不变。长名称以工具提示完整呈现，盘内标签使用单行省略，避免撑大道具盘。

## 拖拽反馈

### 悬停

- 光标变为 `OpenHandCursor`。
- 图标轻微放大或上浮，并增加阴影，表现为“可以拿起”。
- 工具提示改为“拖动〈道具名〉到宠物身上”。

### 按下与拖动

- 左键按下后光标变为 `ClosedHandCursor`。
- 超过系统拖拽阈值后仍使用现有 Qt `QDrag` 和通用 MIME 数据。
- 拖拽副本略大于常态图标并保持透明背景。
- 拖动期间原位置降低图标不透明度或只留下淡槽位，形成物体已被拿起的视觉反馈。
- 拖拽结束或取消时恢复图标、光标和悬停状态。

### 投放目标

沿用现有宠物透明像素命中和命中反馈。道具进入有效宠物区域时继续由宠物窗口负责高亮；道具盘不重复实现目标判断。

## 首次提示

每个 `InteractionItemToolbox` 实例第一次打开非空道具盘时：

- 顶部“拖给宠物”提示以短暂强调状态出现。
- 第一个道具执行一次轻微的放大/浮起再复位动效，持续时间不超过约 700 ms。
- 同一实例后续展开不再播放教学动效。
- 切换宠物和重载时不建立新的持久化设置；若控件实例被完全重建，可以再次提示。
- 当系统减少动画或测试环境不运行事件循环时，静态标题与抓取光标仍能独立表达操作方式。

## 状态与职责

`InteractionItemButton` 负责自身的悬停、按下、拖动和恢复视觉状态，不发布动作事件。`InteractionItemPanel` 负责加载木质置物架 PNG 并按端盖、中段、端盖三段绘制；`InteractionItemToolbox` 负责标题、首次提示、布局和开合。`PetWindow` 继续只负责道具解析、投放命中、事件触发和生命周期清理。

样式使用入口和道具按钮各自的 object name，避免通用 `QToolButton` 选择器让两类控件再次共享错误的按钮外观。

## 测试与验收

### 自动化

- 顶层工具窗口启用透明背景，入口常态无边框、无常驻底色。
- 盒子图形内部有填充，盒盖、折线与轮廓描边完整，渲染尺寸为 25 px。
- 入口悬停与展开状态可通过独立属性或 object name 选择器呈现。
- 道具按钮使用打开手形光标；按下切换抓取光标，释放和拖拽结束后恢复。
- 道具工具提示明确说明拖到宠物身上。
- 道具盘包含“拖给宠物”标题，且最多八个道具和四列规则不变。
- 面板成功加载 RGBA 木质置物架资源，端盖与中段按三段绘制；道具按钮常态与悬停状态具有不同的抬起量。
- 首次展开只触发一次教学状态，后续展开不重复。
- 既有 MIME 数据、拖拽阈值、关闭清理和屏幕边界测试继续通过。

### 人工视觉验收

- 在浅色、深色和复杂桌面背景上，入口没有黑色方框且盒子图形可辨识。
- 常态入口只看到盒子；悬停或展开时才出现柔和光晕。
- 盒子填充不遮挡盒盖或折线，尺寸比之前稍大但不挤压 44 px 命中区域。
- 道具第一眼像木质置物架上的竖立可拿取物，而不是普通按钮或平铺图标。
- 悬停浮起、抓取光标、拖拽副本和原位置槽位形成连续反馈。
- 第一次提示可被注意到但不遮挡宠物，也不在每次打开时重复。

## 成功标准

用户无需先尝试单击，就能从标题、物体式布局、手形光标和浮起反馈判断道具应拖到宠物身上；同时入口在各种桌面背景上清楚可见，且不再出现黑边或常驻圆角矩形底板。
