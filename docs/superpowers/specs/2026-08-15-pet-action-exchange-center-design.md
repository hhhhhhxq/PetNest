# 宠物与动作导入、更新和分享中心设计

## 背景

PetNest 当前有两条相互独立的导入路径：“导入精灵图”用于新建宠物，“导入下班动画”用于给当前宠物安装两个全屏动作。下班动画包要求用户手工组织目录并编写 `manifest.json`，不适合普通用户传递已有动画。同时，它把分享能力限定在下班全屏动画，无法复用到 `idle`、`walk`、`hover`、`click` 或自定义动作。

本次设计将这些入口收敛为统一的“宠物与动作”中心。普通用户只需选择宠物包、动作分享包或标准精灵图；内部清单、路径和 JSON 由应用生成和维护。

## 目标

- 用一个统一窗口承载宠物新增、宠物更新、动作新增、动作更新和动作分享。
- 允许从完整 PetNest 宠物文件夹或 ZIP 中直接挑选动作，不要求额外制作专用包。
- 导出页列出所选宠物的全部动作，支持预览、多选和生成可分享 ZIP。
- 分享范围不限于全屏动画，完整保留动作作用域、画布、时间线、循环和播放属性。
- 导入和更新均在临时候选目录中完成校验，并以单次事务安装；失败不改变现有宠物。
- 保持现有宠物包、旧版下班动画包和 Codex 8×9 精灵图的兼容性。

## 非目标

- 第一版不提供从任意散图手工组帧的通用动画制作器。
- 第一版不从任意视频、GIF、PSD 或非标准精灵图自动生成宠物。
- 动作分享包不包含可执行文件、脚本或插件。
- 第一版不新增完整宠物导出器；“全选动作”仍是动作分享包，不等同于完整宠物包。

## 信息架构

托盘“宠物库”中新增统一入口“宠物与动作…”。打开后使用两个顶层页面：

1. **导入**：新增或更新宠物，新增或更新动作。
2. **导出分享包**：选择宠物和任意数量的动作，生成 ZIP。

现有“导入精灵图…”和“导入下班动画…”在一个过渡版本中保留为快捷入口，但点击后进入统一窗口的对应流程。下一个大版本可删除旧菜单项。

## 导入流程

### 入口选择

导入首页提供两张任务卡片：

- **新增／更新宠物**
- **新增／更新动作**

选择任务后，窗口内部按“选择来源 → 检查内容 → 选择目标与冲突策略 → 确认结果”前进，不再打开第二个对话框。

### 新增／更新宠物

来源类型：

1. **PetNest 宠物文件夹或 ZIP**
   - 允许 ZIP 外层或所选文件夹中多包一层任意名称目录。
   - 递归查找且必须只找到一个可用 `pet.json`。
   - 校验通过后展示名称、ID、版本、作者、预览图、画布和动作数。
   - 库内不存在同 ID 宠物时进入“新增”；存在时进入“更新”。
2. **Codex 标准精灵图 PNG**
   - 复用现有 8×9 布局检查、格位选择、命名和裁帧能力。
   - 表单作为统一窗口内的一个页面，不复制导入逻辑。
   - 第一版仅允许新增宠物；目标 ID 已存在时要求换 ID，不通过精灵图覆盖整包。

#### 同 ID 宠物更新

已确认的默认行为是“整包替换并自动备份”：

1. 候选包在临时目录中通过完整包校验。
2. 将旧包压缩备份到 `<pets-root>/.backups/<pet-id>/<timestamp>.zip`。
3. 使用同目录原子替换宠物包，而不逐文件覆盖。
4. 更新当前宠物时保留窗口位置，重新加载成功后才删除旧运行实例引用。

页面提供“保留本地新增动画”选项。启用时：

- 只保留旧包中“动作 ID 在新包中完全不存在”的动作定义和帧目录。
- 同 ID 动作始终以新包为准，不混合帧。
- 与被保留动作直接相关、且新包未声明的触发绑定和回退条目一并保留。
- 不保留其他任意未知文件，避免把过时素材、临时文件或损坏配置带回候选包。

### 新增／更新动作

来源类型：

1. **PetNest 动作分享包 ZIP 或文件夹**。
2. **完整 PetNest 宠物包 ZIP 或文件夹**，检查后列出其全部动作。
3. **旧版下班动画包**，识别唯一 `manifest.json` 并转换为 `work_finish_walk` 和 `work_finish_lie_down` 两个标准动作。

检查完成后，页面列出源包所有可导入动作。用户可多选，然后选择目标宠物。不允许把 `scope: fullscreen` 擅自转成普通宠物动画，也不允许将普通动画自动放大为全屏动画；作用域作为动作定义的一部分原样保留。

#### 动作冲突

目标宠物已有同 ID 动作时，每个冲突行提供：

- **替换**：用导入动作的定义和全部帧替换同 ID 动作。
- **另存为**：输入新动作 ID，候选包内路径随之改写。
- **跳过**：不安装该动作。

从“更新动作”进入时，同 ID 冲突默认为“替换”，但确认页必须明确列出将被替换的动作。所有动作作为一次原子安装处理；任意帧、定义、绑定或候选包校验失败时全部回滚。

## 导出分享包流程

### 宠物和动作选择

页面顶部是宠物选择器，默认选中当前宠物。中间列出已校验的全部动作，不按作用域隐藏。每行显示：

- 多选框、动作 ID 和已知中文用途。
- `pet` 或 `fullscreen` 作用域。
- 帧数、画布尺寸、循环状态和优先级。
- FPS；声明 `frame_durations_ms` 时显示“逐帧时长”。
- 第一帧缩略图。

页面提供按名称搜索、“全部／宠物动画／全屏动画”筛选、全选和清空。筛选只改变列表显示，不自动取消已选动作。

### 预览

预览区复用动画时长编辑器的棋盘格画布、播放计时和逐帧时长计算，但提取为可复用组件，避免导出页依赖整个编辑对话框。选中任意动作行后可：

- 播放或暂停。
- 点选帧并查看帧编号、单帧时长和透明区域。
- 按画布比例缩放，不把全屏动画直接铺满导出窗口。

帧图像延迟加载并按“宠物 ID + 动作 ID + 文件修改时间”缓存，切换大型宠物时不预先解码全部动画。

### 分享信息与输出

至少选择一个动作后才能导出。用户可填写：

- 分享包名称（默认“<宠物名称> 动作”）。
- 作者（默认源宠物作者，可留空）。
- 说明（可选）。

“导出 ZIP”要求用户选择保存位置。导出器在同目录临时文件中构建包，完整成功后再替换目标 ZIP，避免中断时留下损坏包。

## 通用动作分享包

新格式的唯一内部清单名为 `petnest-action-pack.json`，避免与完整宠物的 `pet.json` 或旧下班包的 `manifest.json` 混淆。用户不需要查看或编辑该文件。

```text
<share-name>.zip
├─ petnest-action-pack.json
├─ preview.png                 # 可选，只用于外部展示
└─ actions/
   ├─ idle/
   │  ├─ 001.png
   │  └─ 002.png
   └─ work_finish_lie_down/
      ├─ 001.png
      └─ 002.png
```

清单顶层字段：

```json
{
  "type": "petnest-animation-pack",
  "schema_version": 1,
  "name": "平安动作分享",
  "author": "",
  "description": "",
  "source_pet": {"id": "pingan", "name": "平安"},
  "animations": {},
  "bindings": {},
  "fallbacks": {}
}
```

`animations` 中每个条目保留 PetNest 当前支持的动作字段：`path`、`fps`、`loop`、`next`、`priority`、`interruptible`、`restart_on_reenter`、`frame_durations_ms`、`speed_multiplier`、`scope` 和可选 `canvas`。导出时把 `path` 改写为分享包内 `actions/<action-id>`；导入时再改写为目标宠物的 `animations/<target-id>`。

包含的 `bindings` 仅限于值直接引用已选动作的条目。`fallbacks` 仅包含与已选动作直接相关的候选关系，且不引用未入包的动作。如无法构成闭合关系，导出器忽略该条回退并在确认页提示。

## 触发绑定

动作帧导入成功不代表它会被目标宠物自动触发。因此分享包记录相关绑定，但导入页把“同时导入触发规则”作为独立选项：

- 默认关闭，避免分享动作意外改变目标宠物行为。
- 启用后列出将新增、替换或跳过的每个绑定。
- 绑定引用“另存为”的动作时自动改写为新 ID。
- 不导入触发规则时，动作仍可在动画编辑器预览，并可后续通过配置或其他功能绑定。

## 来源识别和兼容性

用户首先选择“宠物”或“动作”意图，再选来源，避免仅凭文件名猜测用户意图。在意图范围内按以下顺序识别：

- 单个 PNG 且尺寸、网格符合 Codex 标准时：标准精灵图。
- 解包后恰好一个 `petnest-action-pack.json`：通用动作分享包。
- 恰好一个且可校验的 `pet.json`：完整宠物包。
- 恰好一个旧版 `manifest.json` 且符合下班包 schema：旧版下班动画包。

同一来源同时出现多个候选清单、目录逃逸或无法判定根目录时拒绝导入，不自动选“第一个”。旧格式可继续导入，但所有新导出只产生 `petnest-action-pack.json` 新格式。

## 核心组件

### `PetActionExchangeService`

统一编排检查、安装、导出和原子替换，对 UI 返回不依赖 Qt 的结构化检查结果和变更计划。它不负责显示对话框。

### 来源适配器

- `PetPackageSourceAdapter`：完整宠物文件夹／ZIP。
- `ActionPackSourceAdapter`：新通用动作分享包。
- `LegacyWorkFinishSourceAdapter`：现有下班动画包。
- `SpriteSheetSourceAdapter`：复用现有 `SpriteSheetImporter`。

适配器只把来源转成通用候选模型，安装、冲突解决和回滚不在每个适配器里重复实现。

### `ActionPackExporter`

根据已加载 `PetPackage` 和选中动作生成候选清单、复制帧、改写路径、生成可选预览图并原子写出 ZIP。

### `AnimationPreviewWidget`

从现有动画时长编辑器提取棋盘格、帧加载和时间线播放能力。编辑器、导入检查和导出页使用同一预览实现。

### `PetActionExchangeDialog`

只负责导航、表单状态、预览和用户确认。文件 IO、ZIP 解包、JSON 改写和原子安装全部下沉到核心服务。

## 安全、限制和原子性

- ZIP 和文件夹统一禁止符号链接、路径穿越、重复折叠路径、特殊文件和可执行文件。
- 复用并抽象现有下班导入器的文件数、解压体积和压缩比限制；宠物整包限制可以高于动作包，但必须由明确常量管理。
- 动作包只允许受支持的 JSON 和普通图像文件；第一版输出只包含 PNG。
- 所有帧都由 Pillow 完整解码后校验尺寸和 alpha 通道，不只信任扩展名。
- 导入器先在目标宠物的同父目录构造候选包，通过 `PackageValidator` 后再替换。
- 完整宠物更新先创建可恢复备份。动作安装不创建长期备份，但在事务内保留临时旧目录和 `pet.json`，成功后才删除。
- 当前宠物重载失败时回滚文件替换并重载旧包；仍失败时保留备份并向用户给出可操作的错误和备份位置。

## 页面文案和可理解性

导入首页不用“manifest”、“schema”或“scope”等内部词汇。用户看到的来源说明为：

- “宠物文件夹或 ZIP：导入完整 PetNest 宠物”。
- “Codex 精灵图：从标准 8×9 透明 PNG 创建新宠物”。
- “动作分享包：导入别人从 PetNest 导出的 ZIP”。
- “从宠物中选动作：直接从完整宠物文件夹或 ZIP 提取”。

检查失败时给出“选了什么、缺什么、如何修复”，而不只显示“包无效”。确认页用变更摘要列出新增、替换、改名、跳过的宠物或动作数量。

## 集成与运行时行为

- 新增宠物完成后重新扫描宠物库，默认切换到新宠物。
- 更新非当前宠物后只刷新列表；更新当前宠物后原位重载。
- 导入动作到当前宠物后立即重载，导入到其他宠物后只更新其库记录。
- 动画编辑器、托盘宠物名称、当前动作和下班提醒的资源解析在重载后统一取新 `PetPackage`。
- 如果全屏下班提醒正在显示，导入或更新当前宠物前必须先让用户关闭提醒，不在进行中替换其帧资源。

## 测试策略

### 核心服务

- 新动作包导出再导入后，所有受支持的动作属性和 PNG 字节保持一致。
- 从完整宠物包提取任意宠物动画和全屏动画。
- 新增、替换、另存为和跳过的混合冲突计划。
- “另存为”时正确改写路径和可选绑定。
- 整包更新备份、默认替换、保留本地新增动作和回滚。
- 旧下班包和现有精灵图导入结果保持兼容。
- 恶意 ZIP、压缩炸弹、符号链接、多清单、损坏图像和候选包失效全部被拒绝。

### UI

- 导入任务切换、来源检查、宠物目标选择、动作多选和冲突行为。
- 导出宠物切换、搜索、作用域筛选、全选、预览和空选禁用。
- 预览播放使用 FPS 和逐帧时长，切换动作后计时器不泄漏。
- 更新当前宠物成功时重载，失败时回滚并保留可用旧宠物。

### 完整回归

- 宠物包加载、校验、动画编辑、托盘、精灵图导入和下班提醒回归。
- 通过“导出选中动作 → 导入到另一宠物 → 重载 → 预览”的端到端流程。

## 实施分期

1. 通用来源模型、安全解包、动作分享包 schema、导出器和导入事务。
2. 可复用动画预览组件和导出页。
3. 从分享包和完整宠物包导入选定动作，含冲突与可选绑定。
4. 完整宠物文件夹／ZIP 新增与更新，含备份和保留本地新增动作。
5. 精灵图导入页嵌入、旧下班包适配和托盘入口收敛。
6. 安全、回滚、端到端和完整回归验证。

## 验收标准

- 普通用户能直接选择完整 `pingan` 文件夹，预览并把任意选中动作导入到另一宠物。
- 用户能选择宠物的任意数量动作，在应用中预览并导出一个可被另一实例直接导入的 ZIP。
- 整个常规分享流程不要求用户创建目录、命名帧、编写 JSON 或理解内部作用域。
- 同 ID 宠物更新默认整包替换并产生备份；启用“保留本地新增动作”时，不丢失仅存在于旧包的动作。
- 新增或替换多个动作时不会留下部分成功状态；安装失败后原宠物仍可加载和播放。
- 现有精灵图导入和旧下班动画包仍可通过统一窗口完成。
