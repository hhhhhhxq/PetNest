# 局域网互动幽灵用户修复设计

## 问题

运行测试时，应用级测试会创建使用随机设备 ID 的临时 PetNest 实例。这些实例默认启动真实的局域网发现服务，并向正在运行的 PetNest 广播 `hello`。互动窗口因此把测试实例显示成大量 `用户-XXXX`，预警组名单也会持久化这些临时身份。

现场数据已经确认这些异常身份均指向本机同一个网络端点 `192.168.101.14:18487`，并且设备 ID 不同。

## 目标

- 测试创建的临时应用不得向真实局域网广播。
- 同一个网络端点不能同时显示为多个不同设备。
- 自动清理已经写入预警组名单、且与本机端点冲突的旧身份。
- 不影响不同 IP 或不同端口上的真实设备。
- 不根据昵称、默认名称或在线状态判断真假用户。

## 方案

### 测试网络隔离

测试环境设置专用的“禁用应用级 LAN”开关。`PetNest` 的自动配置流程识别该开关后，不启动 `LanInteractionService` 和 `LanPoolSyncService`。

专门测试局域网协议和服务的用例仍可直接创建 `LanInteractionService`，因此协议、发现和收发测试不被跳过。

生产环境默认行为保持不变。

### 运行时端点去重

附近设备以 `(来源 IP, 对方声明端口)` 作为端点。收到新身份时，如果同一端点已经对应另一个未保存的临时身份，则移除旧身份后再加入新身份，确保列表中一个端点最多出现一次。

已经由用户手动保存的伙伴不允许被未经验证的新身份静默覆盖；出现冲突时沿用现有身份校验逻辑。

### 持久名单清理

本机加入或刷新预警组记录时，名单存储删除所有“设备 ID 不是本机、但 IP 和端口都与本机完全相同”的记录。不同 IP、不同端口以及用户保存的远程伙伴不受影响。

清理与本机记录更新在同一次原子写入中完成，避免崩溃后留下半更新文件。

## 边界情况

- 同一 IP 上的多台设备如果端口不同，全部保留。
- 不同 IP 上使用相同端口的设备，全部保留。
- 相同昵称或相同默认名称不会触发清理。
- 只有 IP 和端口同时相同才认定端点冲突。
- 已保存伙伴发生身份冲突时拒绝覆盖，并保留可理解的错误提示。
- 测试禁用开关只影响 `PetNest` 的自动启动流程，不改变底层 LAN 服务的可测试性。
- LAN 已关闭时重复配置或关闭服务保持幂等。
- 损坏或不可写的名单文件继续沿用现有隔离和报错策略，不静默覆盖原文件。

## 测试

1. 应用级测试启用隔离开关后，LAN 服务和预警组同步均不启动。
2. 底层 LAN 服务测试在隔离开关存在时仍可直接启动。
3. 同一端点连续报告两个未保存设备 ID 时，最终只保留最新身份，并发出旧身份移除通知。
4. 不同 IP 或不同端口的设备不会被去重。
5. 已保存伙伴不会被同端点的新身份覆盖。
6. 更新本机预警组记录会清理同端点旧身份，但保留其他端点记录。
7. 清理后重新载入名单结果一致，且现有局域网与互动窗口测试全部通过。

## 不在本次范围

- 不修改局域网协议版本。
- 不改变用户昵称或设备 ID 的生成规则。
- 不按时间批量删除正常的离线预警组成员。
- 不改变远程伙伴功能。
