# 逗猫棒按住拖拽陪玩模式设计

## 背景

PetNest 当前的互动道具采用统一拖放语义：用户从道具箱按住道具，将其拖到宠物的不透明像素上，松手后触发一次由宠物包绑定的动画。平安 V2 已有一次性 `playing_toy` 动作，并已准备六组新的陪玩动作资源，但这些资源使用 `512×384` 画布，大于宠物包当前的 `384×256` 默认画布。

本功能在不改变其他道具行为的前提下，让逗猫棒在“按住并拖入宠物画布”期间持续驱动平安朝鼠标目标扑抓。松手仍沿用“把道具交给宠物”的含义：画布内松手播放原有 `playing_toy`，画布外松手取消。

## 目标

- 保持单一、可预测的拖拽语义，不增加单击进入持久模式的第二套入口。
- 按住逗猫棒并进入宠物画布后，以鼠标位置驱动五方向扑抓。
- 使用临时 `512×384` 交互画布完整展示向上和横向动作，同时保持猫的可见大小和脚底屏幕位置稳定。
- 在画布内松手时触发该道具可选的普通投放绑定；在画布外松手时不触发该绑定。
- 允许宠物包按道具自由选择是否启用 `hold_play`、每个方向绑定什么动作，以及是否提供松手后的普通投放动作。
- 保持其他道具、普通宠物拖拽、鼠标跟随、倒计时和现有状态机行为不变。
- 将功能设计与代码提交，平安 V2 宠物资源继续保持未跟踪，不进入代码提交。

## 非目标

- 不提供单击锁定、`Esc` 退出或无限持续的陪玩模式。
- 不让宠物窗口跟随鼠标跨桌面移动。
- 不在 V1 中增加近距离 `reach` 专用动作或八方向动作。
- 不让平安在鼠标静止不动时自动重复扑同一个位置。
- 不修改食物、水、猫条和猫砂盆的现有拖放命中规则。

## 交互语义

### 基本流程

1. 用户在道具箱中按住逗猫棒并超过系统拖拽阈值。
2. 逗猫棒进入宠物当前画布时，PetWindow 开启临时陪玩会话。
3. 窗口以屏幕上的脚底中心为锚点，从默认画布扩展为 `512×384`；平安播放 `toy_ready`。
4. 拖拽图像在有效画布内显示为逗猫棒，热点位于吊坠中心。
5. 鼠标移动时只更新目标。目标稳定 140 ms 后，平安播放对应方向的一次扑抓。
6. 扑抓期间不切换动作，只缓存最新目标。
7. 扑抓结束并冷却 350 ms 后回到 `toy_ready`。只有鼠标相对上次攻击目标移动至少 24 px，才允许再次触发。
8. 用户在画布内松手：
   - 若道具有普通投放绑定，平安处于 `toy_ready` 时立即收起交互画布并播放该绑定动作。
   - 若道具有普通投放绑定且扑抓尚未落地，记录一次待完成投放；当前扑抓自然播放到结尾后，收起交互画布并播放绑定动作。
   - 若道具没有普通投放绑定，结束陪玩并恢复进入前状态，不额外播放动画。
9. 用户拖出画布：临时停止陪玩并恢复进入前的动作和默认画布；继续按住并再次拖入时可重新开启。
10. 用户在画布外松手：取消拖拽并结束会话，不播放 `playing_toy`。

### 异常结束

切换宠物、开启鼠标跟随、关闭鼠标交互、隐藏窗口、窗口销毁或原生拖放异常结束时，必须统一清理陪玩会话，恢复原动作、默认画布、倒计时可见性和鼠标外观。

## 方案比较

### 方案 A：扩展现有 Qt 原生拖放（采用）

复用 `QDrag.exec()` 及 PetWindow 已有的 `dragEnterEvent`、`dragMoveEvent`、`dragLeaveEvent`、`dropEvent`。拖放嵌套事件循环继续驱动动画计时器，PetWindow 在拖拽进入期间维护临时陪玩会话。

优点是沿用现有跨窗口拖放、释放位置判断和平台行为；其他道具无需改写。风险是 Windows 与 macOS 对原生拖拽光标的展示略有差异，因此需要独立的输入透明光标覆盖层作为一致性回退。

### 方案 B：自定义全局鼠标捕获（不采用）

按住按钮后使用 `grabMouse()` 和全局坐标自行模拟拖拽。它能完全控制光标，但窗口切换、失焦、多屏和 macOS 原生窗口层级更容易造成鼠标未释放或状态卡住。

### 方案 C：单击进入持久模式（不采用）

单击选择逗猫棒、再次单击或按键退出。它适合长时间陪玩，但和当前“拖给宠物”的含义并列，用户无法仅凭按钮外观判断单击与拖动的不同结果。

## 宠物包模型

### 独立宠物动作画布

允许 `scope: "pet"` 的动画声明可选 `canvas`。省略时继续使用包级画布；声明时，所有帧必须严格匹配该尺寸。

```json
{
  "toy_ready": {
    "path": "animations/toy_ready",
    "fps": 8,
    "loop": true,
    "priority": 75,
    "interruptible": true,
    "canvas": {"width": 512, "height": 384}
  }
}
```

PetWindow 根据当前播放动作选择动作级或包级画布。画布切换时保持屏幕上的底部中心锚点不变，避免猫整体跳位。

### 按住陪玩型道具

`interaction_items` 条目增加可选 `hold_play`。未声明时行为完全保持不变。

```json
{
  "id": "toy_wand",
  "label": "逗猫棒",
  "icon": "items/toy_wand.png",
  "hold_play": {
    "cursor": "items/toy_wand.png",
    "cursor_hotspot": [100, 105],
    "ready_action": "toy_ready",
    "attack_origin": [256, 310],
    "settle_ms": 140,
    "cooldown_ms": 350,
    "rearm_distance": 24,
    "targets": {
      "center": {
        "action": "toy_pounce_center",
        "contact_frame": 12,
        "contact_point": [256, 180],
        "max_correction": [12, 10]
      },
      "left": {
        "action": "toy_pounce_left",
        "contact_frame": 18,
        "contact_point": [19, 168],
        "max_correction": [12, 10]
      },
      "right": {
        "action": "toy_pounce_right",
        "contact_frame": 18,
        "contact_point": [492, 168],
        "max_correction": [12, 10]
      },
      "up_left": {
        "action": "toy_pounce_up_left",
        "contact_frame": 18,
        "contact_point": [174, 72],
        "max_correction": [12, 10]
      },
      "up_right": {
        "action": "toy_pounce_up_right",
        "contact_frame": 18,
        "contact_point": [337, 72],
        "max_correction": [12, 10]
      }
    }
  }
}
```

现有绑定 `interaction.item.toy_wand: playing_toy` 继续代表“画布内松手后的最终投放动作”。因此陪玩配置不复制或替代原绑定。该绑定是可选的；只有 `hold_play` 的道具也能显示和使用，画布内松手时直接结束陪玩。

### 数据模型

新增不可变模型：

- `HoldPlayDefinition`：光标、热点、ready 动作、攻击原点、稳定/冷却/重触发参数和五方向目标。
- `HoldPlayTargetDefinition`：动作名、接触帧、接触点和最大校正范围。
- `InteractionItemDefinition.hold_play`：可选的按住陪玩配置。

验证失败时忽略该道具的 `hold_play` 并产生警告；若普通投放绑定有效，仍保留普通拖放，避免一个可选增强破坏整个宠物包。道具只要普通投放绑定或 `hold_play` 至少一项有效就显示；两项都无效才从道具箱隐藏。动作本身声明了错误画布或帧尺寸时仍按现有规则判定宠物包无效。

## 目标判定

新增不依赖 Qt 的 `HoldPlayController`，输入逻辑画布坐标和时间，输出 `ready`、某个攻击方向或无变化。

以 `[256, 310]` 为攻击原点计算 `dx`、`dy`：

- `dy < -60` 且 `dx < 0`：`up_left`
- `dy < -60` 且 `dx >= 0`：`up_right`
- `|dx| <= 60`：`center`
- `dx < -60`：`left`
- `dx > 60`：`right`

目标必须在 18 px 抖动半径内保持 140 ms 才算稳定。一次攻击完成后进入 350 ms 冷却；即使冷却结束，目标未相对上次攻击位置移动至少 24 px 时也不会再次攻击。

方向 target 不要求全部提供，但必须至少提供 `center`。缺少方向时按以下顺序回退，最终可让所有方向复用同一个动作：

- `up_left → left → center`
- `up_right → right → center`
- `left → center`
- `right → center`

所有 target 的 `action` 都是宠物包声明的任意动作名，代码不识别 `toy_*` 前缀，也不识别逗猫棒、激光笔或其他具体物品名称。

攻击开始后方向锁定。鼠标移动仅更新下一候选目标，不改变当前动画。接触帧前后才应用位置校正，校正量按目标与名义接触点之差计算并受 `max_correction` 限制，其他帧保持零偏移，避免整只猫滑动。

## 窗口与渲染

- 普通状态继续使用包级 `384×256` 画布。
- 陪玩动作使用各自动画声明的 `512×384` 画布。
- 切换画布前记录当前窗口的底部中心全局坐标；调整固定尺寸后以该坐标重新定位。
- 动作帧按其逻辑画布和当前宠物缩放比例绘制，不额外缩放猫。
- 倒计时在陪玩会话期间临时隐藏，会话结束后恢复，不修改倒计时数据。
- 目标坐标使用动作逻辑画布坐标，不使用包级画布中心，也不要求命中猫的不透明像素。
- 陪玩画布的透明区域在会话期间是有效目标区；会话结束后窗口立即缩回，避免长期遮挡桌面输入。

## 拖拽光标

现有 `toy_wand.png` 为 `128×128 RGBA`，吊坠中心热点为 `[100, 105]`。V1 使用输入透明、无焦点的置顶小覆盖层绘制逗猫棒，并让热点跟随 `dragMoveEvent` 的全局位置。

- 拖拽在画布外：覆盖层隐藏，保留平台默认拖放反馈。
- 拖拽进入有效陪玩画布：覆盖层显示，原生拖拽图像改为空白或最小透明像素。
- 拖出、松手或异常结束：覆盖层立即隐藏。
- 覆盖层不接收鼠标，不参与目标命中，也不改变宠物窗口层级。

若目标平台能稳定显示 `QDrag.setDragCursor()` 的自定义 MoveAction 光标，可优先使用原生光标；覆盖层仍作为平台一致性回退。

## 组件职责

### `pet_package.py`、`package_validator.py`、`package_loader.py`

负责可选配置的数据模型、安全路径、数值范围、动作引用、统一动作画布和帧尺寸校验。

### `interaction_items.py`

分别解析道具的可选普通投放动作和可选 `hold_play`。只要其中一项有效就返回道具；缺失方向在解析时按同侧和 center 规则补齐。

### `interaction_play.py`

新增纯逻辑控制器，负责方向、稳定判定、冷却、重触发距离、攻击锁定和待完成投放状态，不依赖 Qt 或图片资源。

### `interaction_item_toolbox.py`

继续创建原生 `QDrag`；暴露拖拽开始/结束生命周期，并为按住陪玩型道具提供可切换的拖拽视觉。

### `pet_window.py`

负责拖拽事件接线、临时画布、动作播放、接触帧校正、光标覆盖层和所有退出路径的统一清理。普通道具仍按不透明像素命中，只有声明 `hold_play` 的道具按临时画布命中。

## 状态

陪玩会话包含以下状态：

- `inactive`：无陪玩拖拽。
- `ready`：拖拽位于画布内，播放 `toy_ready`，等待稳定目标。
- `attacking`：播放锁定方向的扑抓动作。
- `cooldown`：扑抓结束，播放 `toy_ready`，等待冷却和目标重移动。
- `pending_drop`：用户已在画布内松手，且道具有普通投放绑定，等待当前扑抓自然落地。
- `suspended`：仍按住道具但已拖出画布；恢复默认画布和进入前动作。

任何状态都必须能通过统一 `cancel()` 回到 `inactive`。`pending_drop` 完成后通过原有道具绑定触发该宠物自行配置的动作；没有普通绑定时不会进入 `pending_drop`。

## 测试策略

### 纯逻辑测试

- 五方向边界和坐标转换。
- 140 ms 稳定判定及 18 px 抖动容忍。
- 350 ms 冷却和 24 px 重触发距离。
- 攻击期间方向锁定及下一目标缓存。
- 画布内/外松手与 `pending_drop`。

### 包模型测试

- pet 动作可声明独立画布，旧包行为不变。
- 独立画布帧尺寸严格校验。
- `hold_play` 图标路径、热点、数值范围、动作引用和统一画布验证。
- 无效 `hold_play` 产生警告并回退普通拖放。
- 仅普通绑定、仅 `hold_play`、两者都有和两者都无效的道具显示规则。
- 缺失方向按 `上方→同侧→center` 回退，并允许多个方向复用同一动作。

### Qt 测试

- 普通道具仍只在不透明像素上接受投放。
- 逗猫棒进入后扩展画布，底部中心全局坐标不变。
- 拖拽移动驱动方向，透明画布区域也可作为目标。
- 拖出恢复、再次拖入重启、画布外松手取消。
- 画布内松手在 ready 时立即播放 `playing_toy`。
- 攻击中松手等待自然落地，再播放 `playing_toy`。
- 拖拽异常结束、切宠物、鼠标跟随和关闭窗口都能清理覆盖层与临时画布。
- 左右镜像动作和接触帧校正不触边。

### 回归测试

- 现有互动道具测试、PetWindow 鼠标拖动测试、鼠标跟随测试和包加载测试全部保留。
- 手动在 Windows 与 macOS 验证原生拖放过程中覆盖层、焦点和松手事件。

## 验收标准

- 用户必须持续按住逗猫棒，平安才进入陪玩交互。
- 鼠标进入陪玩画布后 140 ms 左右开始响应，快速划过不会误扑。
- 同一静止目标只扑一次；移动逗猫棒后可再次触发。
- 扑抓动作不被鼠标中途移动打断。
- 画布内松手最终播放该道具的可选普通绑定动作；没有该绑定时只结束陪玩。画布外松手不播放。
- 进入和退出 `512×384` 画布时猫的脚底位置和可见大小不跳变。
- 任何退出路径都不会遗留覆盖层、扩大画布或错误鼠标状态。
- 未声明 `hold_play` 的宠物包和道具行为不变。
