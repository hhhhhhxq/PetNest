# 宠物与动作中心默认选择与安装反馈设计

## 问题

动作安装已经完成时，导入页只更新统一窗口底部的短文本，没有明确的成功通知。动作包写入磁盘后还要经过当前宠物运行时重载；现有页面在磁盘提交后立即认为成功，无法区分运行时重载成功、已回滚或回滚失败。

统一窗口构造时只把 `current_pet_id` 传给动作编辑页。动作导入页和动作导出页按包列表顺序选中第一项，因此打开窗口时不一定指向当前正在运行的宠物。

## 目标行为

- 打开“宠物与动作”时，所有拥有宠物选择器的页面默认选中当前宠物：导入动作、编辑动作、导出动作。
- 当前宠物 ID 不存在时安全回退到第一只可用宠物；无宠物时保持空选择。
- 动作资源写入后先显示“正在应用”，只有应用层完成当前宠物重载后才显示成功通知。
- 开始复制和校验前显示“正在安装 N 个动作…”，禁用主按钮并刷新一次 Qt 事件循环，确保提示在同步安装阻塞 UI 前可见。
- 磁盘安装异常显示明确错误弹窗，并在底部保留可复制的错误信息。
- 当前宠物重载失败并回滚时，不显示成功通知，不清空导入内容。
- 安装真正生效后，清空本次来源路径、来源摘要、动作列表、冲突表和“同时导入相关绑定”，保留目标宠物选择及“已导入 N 个动作”的结果状态。

## 设计

### 默认宠物

`ActionImportPage` 和 `ActionExportPage` 增加可选的 `current_pet_id` 构造参数。`PetActionExchangeDialog` 计算一次有效的 `desired_id`，并传给导入、编辑和导出三个页面。每个页面都使用同一规则：找到该 ID 就选中；否则选择第一项；列表为空则保持 `-1`。

“导入宠物”页面没有目标宠物选择器，因此不参与默认选择。

### 安装结果责任

`ActionImportPage` 负责：

- 前置条件提示；
- 执行动作资源安装；
- 捕获磁盘安装异常并显示 warning；
- 磁盘提交成功后显示“正在应用 N 个动作”，随后发出 `actions_installed`。
- 安装处理中忽略重复触发；磁盘提交成功后把状态切换为“动作已写入，正在重新加载目标宠物…”。

`PetNest` 应用层负责：

- 当前宠物重载成功或非当前宠物提交完成后，调用统一窗口的完成方法并显示 information；
- 重载失败时执行已有回滚流程，只显示失败或恢复提示，不调用完成方法。
- 所有失败/回滚分支都调用页面失败完成方法：恢复按钮、保留来源和选择，并显示最终失败原因。

`PetActionExchangeDialog.complete_action_install()` 把结果转交给动作导入页。页面关闭来源包持有的临时目录，清空本次表单数据，保留目标宠物选择，并把 footer 固定为最终成功状态。

## 边界安全

- 清空来源前必须先完成资源复制和当前宠物重载；临时来源提前关闭不得影响已安装动作。
- 清空过程不修改宠物目录，只释放来源临时目录和重置控件。
- 失败或回滚路径不关闭来源包，用户可以直接再次安装。
- 完成通知方法不存在时，应用层安全跳过页面重置，不能影响已成功的安装结果。
- 非当前宠物安装成功同样清空表单并提示实际目标宠物名称。

## 测试

- 构造统一窗口时，导入动作、编辑动作、导出动作均选择传入的当前宠物。
- 无效当前 ID 回退第一项；空包列表不崩溃。
- 磁盘安装成功后先发出结果，不提前清空来源。
- 应用重载成功后清空来源表单、保留目标选择并显示成功通知。
- 应用重载失败并回滚时不调用清空方法。
- 安装异常保留来源并显示 warning 和 footer 错误。
