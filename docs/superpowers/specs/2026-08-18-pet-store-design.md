# PetNest 宠物商店设计

## 背景

PetNest 已有“宠物与动作”统一窗口、完整宠物包导入与更新能力，以及通过私有 `petnest-resources` 仓库和 Cloudflare Worker 下发资源的链路。当前远程资源目录只服务光标、互动动效和倒计时背景，不适合直接承载商品展示、筛选、领养状态和宠物包更新。

本设计在现有“宠物与动作”窗口中新增原生“宠物商店”页面。商店首版只提供官方精选的完整宠物包，支持浏览、查看详情、领养和内容更新；商店不负责切换、停用或删除宠物。

## 目标

- 在 PySide6 桌面应用内提供风格统一、可离线回退的宠物商店页面。
- 通过现有私有资源仓库和 Worker 发布官方精选宠物，不新增账号、支付或上传系统。
- 首页支持推荐位、搜索、标签筛选和商品卡片，并直接标识“已领养”或“可更新”。
- 详情页按需播放轻量 `idle` 预览，显示简介、标签、动作数、下载大小和最后更新时间。
- 宠物包下载后复用现有安全校验、备份和原子安装流程；失败时不破坏已安装宠物。
- 发布者不需要维护商店版本号。商店展示最后更新时间，客户端使用包的 SHA-256 判断更新。

## 非目标

- 首版不销售或展示动作包、光标、互动动效和倒计时皮肤。
- 首版不允许用户上传、投稿、评论、评分或直接发布宠物。
- 首版不提供付费、账号、收藏、云端领养记录或跨设备同步。
- 商店不承担宠物切换、停用、删除和版本回退；这些能力继续归现有宠物库或备份机制管理。
- 首版不做独立网页商店，也不从浏览器打开外部商店。

## 信息架构

“宠物与动作”窗口左侧导航增加“宠物商店”，形成以下页面顺序：

1. 导入宠物
2. 宠物商店
3. 导入动作
4. 编辑动作
5. 导出动作

商店页面内部只有两级：

- 商店首页：推荐位、搜索、标签筛选和宠物卡片网格。
- 宠物详情：返回入口、动画预览、商品信息和统一底栏操作。

商店使用现有 `ExchangePage` 底部命令协议。页面主体不重复放置主要安装按钮；领养、更新和下载进度统一显示在窗口底栏。

## 首页设计

首页采用“推荐位 + 分类网格”布局：

- 顶部左侧显示“发现新伙伴”和一句辅助说明，右侧提供搜索框。
- 推荐位展示一个由目录指定的精选宠物，包含封面、短描述和“查看详情”。
- 推荐位下方显示“全部”、常用标签和“已领养”筛选项。
- 卡片采用三列自适应网格，显示封面、名称、动作数、下载大小和最后更新时间。
- 搜索匹配宠物名称、作者和标签；搜索与标签筛选在本地完成，不向 Worker 发送查询文本。
- 首版数据量较小时一次加载完整目录，不实现分页和无限滚动。

卡片状态规则：

- 未领养：不显示状态角标，卡片信息区显示“领养”。
- 已安装且本地记录的包摘要等于目录摘要：显示深色“已领养”角标。
- 已安装且目录包摘要与本地记录不同：显示橙色“可更新”角标。
- 本地存在同 ID 宠物但没有商店安装记录：显示“本地已有”角标，不把它误判为已领养或可更新。

“已领养”是面向用户的文案，其精确定义是“当前电脑存在该宠物，并且有对应的商店安装记录”。

## 详情页设计

详情页左侧显示透明棋盘格预览区，按目录中的预览时间线播放 `idle` 预览。右侧显示：

- 宠物名称和作者。
- 简短介绍和标签。
- 动作数量、完整包下载大小和最后更新时间。
- 从元数据提取的能力摘要，例如支持的鼠标交互和任务状态动作。

详情页底栏严格限定为下载和更新职责：

- 未领养：显示下载大小，主按钮为“领养”。
- 已领养且没有更新：说明本机内容与商店一致，主按钮显示不可点击的“已领养”。
- 可更新：说明远程内容最后更新时间，主按钮为“更新”。
- 下载中：显示已下载字节、总大小和百分比，主按钮禁用；次按钮允许取消当前下载。
- 校验或安装中：显示当前阶段，按钮禁用，避免重复提交。

详情页不显示“切换使用”“重新下载”“删除”或“版本回退”。

## 资源仓库结构

现有私有 `petnest-resources` 仓库新增独立的商店目录：

```text
store/
├─ catalog.json
└─ pets/
   └─ <pet-id>/
      ├─ listing.json
      ├─ cover.png
      ├─ idle-preview.png
      └─ package.zip
tools/
├─ build_store_catalog.py
└─ publish_pet.py
```

文件职责：

- `listing.json` 保存需要人工编写的商品文案和标签，不包含版本号、文件大小、摘要、动作数或更新时间。
- `cover.png` 是首页和详情页的静态封面。
- `idle-preview.png` 是由少量代表帧组成的横向精灵图；帧尺寸、帧数和逐帧时长写入生成的目录。
- `package.zip` 是可直接交给现有完整宠物包导入器的 ZIP。
- `catalog.json` 完全由工具生成，不手工维护。

Worker 只公开 `catalog.json` 以及目录白名单中引用的封面、预览和 ZIP。`listing.json`、构建工具和其他仓库文件不会通过 Worker 暴露。

## 商店目录协议

`catalog.json` 使用独立 schema，不并入现有远程运行时资源 `manifest.json`。顶层结构为：

```json
{
  "schema_version": 1,
  "generated_at": "2026-08-18T06:00:00Z",
  "featured_pet_id": "miffy",
  "pets": []
}
```

每个 `pets` 条目包含：

- `id`、`name`、`author`、`summary` 和 `tags`。
- `updated_at`：该宠物内容最后一次发布变化的 UTC 时间。
- `action_count`：从 ZIP 内 `pet.json` 自动提取。
- `capabilities`：由已知 bindings 和 animations 自动归纳的展示能力；未知动作不自动生成营销文案。
- `cover`：`path`、`size`、`sha256`。
- `idle_preview`：`path`、`size`、`sha256`、单帧宽高、帧数和 `frame_durations_ms`。
- `package`：`path`、`size`、`sha256`。

目录解析必须拒绝未知 schema、重复宠物 ID、绝对路径、`..`、反斜杠路径、越出 `store/pets/` 的文件、非法 SHA-256、非正数大小和不完整的预览时间线。目录允许忽略未来新增的非安全关键展示字段，但所有下载与路径字段必须严格验证。

## 无版本号的发布规则

商店不显示或要求维护语义版本号。现有宠物包 `pet.json` 中的 `version` 字段为包格式兼容字段，可以继续存在，但不参与商店更新判断。

`build_store_catalog.py` 读取上一份有效目录并计算新 ZIP 的 SHA-256：

- 新增宠物：`updated_at` 写入当前 UTC 发布时间。
- ZIP 摘要发生变化：`updated_at` 更新为当前 UTC 发布时间。
- ZIP 摘要未变化：沿用上一份目录中的 `updated_at`，重新生成目录不会让全部商品看起来同时更新。
- 封面、预览或商品文案单独变化：更新 `updated_at`，因为用户可见的商品内容已经改变；客户端仍只依据 ZIP 摘要决定是否显示“可更新”。

生成工具必须稳定排序宠物、标签和文件字段。相同输入与相同上一份目录应生成一致结果，只有真实商品变化才改变对应条目。

`publish_pet.py` 接受一个已校验的 PetNest 宠物目录和商品文案，生成 ZIP、封面、轻量预览与 `listing.json`，再调用目录生成器。它不直接推送 Git，也不接触 GitHub Token。

## Worker 接口

Worker 在现有接口之外新增：

- `GET|HEAD /v1/store/catalog.json`
- `GET|HEAD /v1/store/files/<path>?sha256=<64-char-sha256>`

行为要求：

- 商店目录响应使用 `Cache-Control: no-store`，确保手动刷新能看到最新目录。
- 商店文件必须出现在当前商店目录白名单中，且查询参数摘要必须与目录完全匹配。
- 带正确摘要的文件响应使用长期 immutable 缓存；内容变化后 URL 查询参数随摘要变化。
- 商店白名单与现有运行时资源白名单相互独立，最多在 Worker isolate 内缓存 10 秒。
- 继续拒绝非 GET/HEAD/OPTIONS 方法、空路径、重复分隔符、`.`、`..`、反斜杠和 URL 解码错误。
- GitHub Token 继续只保存在 Worker Secret 中，不进入客户端、目录或仓库文件。

## 客户端组件边界

### `PetStoreCatalog`

不依赖 Qt 的目录模型和解析器，负责 schema、字段、路径、大小、摘要和引用一致性校验。

### `PetStoreCache`

负责目录、封面、预览和 ZIP 的本地缓存。缓存目录位于应用数据目录：

```text
pet-store/
├─ catalog.json
├─ state.json
├─ media/<sha256>/...
├─ packages/<sha256>.zip
└─ staging/<run-id>/...
```

只有校验成功的文件才能进入按摘要命名的不可变缓存。临时下载位于 `staging`，取消、失败或进程重启后的遗留 staging 可以安全清理。

### `PetStoreService`

负责后台获取目录、计算展示状态、按需下载媒体、下载宠物 ZIP，并调用现有宠物包导入服务。它返回不依赖具体控件的结构化状态和错误，不负责弹窗或文案布局。

### `PetStorePage`

作为新的 `ExchangePage`，负责首页与详情页导航、搜索筛选、卡片渲染、预览播放和底栏状态。网络、文件校验和安装在后台任务中执行，主线程只处理状态更新。

### 现有安装组件

完整宠物包的安全解包、`PackageValidator` 校验、同 ID 备份、原子替换、回滚和运行时刷新继续复用现有 `PetPackageImporter` 相关能力。商店不得实现第二套覆盖逻辑。

## 本地领养记录

`state.json` 以宠物 ID 保存：

- 已成功安装的 `package_sha256`。
- `installed_at`。
- 最近一次成功安装时目录中的 `updated_at`。

只有完整安装和运行时刷新成功后才写入记录。判断规则为：

1. 目标宠物目录不存在：未领养；存在的过期记录在后台清理。
2. 目录存在但没有记录：本地已有。
3. 目录存在、记录存在且摘要等于远程摘要：已领养。
4. 目录存在、记录存在且摘要不同：可更新。

首版不递归计算已安装宠物目录的内容摘要。用户对已安装目录的本地修改不会自动改变商店状态；远程内容更新时仍按现有备份与替换规则处理。

## 数据流

### 浏览

1. 打开商店页时立即读取最后一份已验证目录缓存。
2. 后台请求最新目录；成功验证后替换缓存并刷新卡片，失败时保留旧目录。
3. 可见卡片按需加载封面，滚出视口的卡片不预取大图。
4. 搜索、标签和领养状态筛选全部在本地执行。

### 查看详情

1. 用户打开详情后加载该商品的完整目录信息。
2. 本地没有对应摘要的预览时，从 Worker 下载单张预览精灵图并校验。
3. 客户端按目录中的帧尺寸裁切，在内存中按逐帧时长播放；不写出临时帧文件。
4. 预览失败时保留静态封面和文字详情，不影响领养。

### 领养或更新

1. 下载前重新读取当前目录条目，冻结本次操作使用的路径、大小和摘要。
2. ZIP 下载到 staging，实时更新底栏进度；用户取消时删除临时文件。
3. 下载完成后校验声明大小和 SHA-256，再通过现有安全来源与宠物包校验。
4. 新宠物直接安装；已知商店宠物按同 ID 更新流程备份并原子替换。
5. 本地同 ID 且没有商店记录时，先展示“本地已有同名宠物”的明确确认；确认后才按更新流程备份和替换。
6. 当前宠物被全屏提醒等资源租约锁定时拒绝更新，并提示用户先关闭占用资源的功能。
7. 文件安装、运行时刷新和宠物库重新扫描全部成功后写入领养记录。商店不自动切换当前宠物。

## 并发和生命周期

- 同一时间只允许一个宠物 ZIP 下载或安装，避免两个更新同时改写宠物库。
- 切换到其他“宠物与动作”页面时，封面和预览任务可以取消；正在下载的宠物包必须由用户明确取消或继续，不静默中断。
- 关闭窗口时若正在下载，提示取消下载或继续留在窗口；安装进入原子替换阶段后禁止关闭，直到成功或回滚结束。
- 目录刷新不得改变正在进行的安装快照；本次操作始终使用点击时冻结的摘要。

## 错误处理

- 首次加载且无缓存：显示错误原因和“重试”。
- 有缓存但网络失败：继续展示缓存，并标注“离线内容”。
- 单个封面失败：显示统一占位图，不隐藏其他卡片。
- 单个预览失败：回退静态封面，领养按钮仍可用。
- 目录格式、路径或摘要非法：拒绝整份新目录，保留最后一份有效缓存。
- ZIP 网络失败、大小不符或摘要不符：删除 staging，保留旧宠物和领养记录。
- 宠物包校验失败：显示缺失或非法内容，不进入安装阶段。
- 更新安装失败：自动回滚旧宠物，不更新领养记录，并给出备份或失败原因。
- 运行时刷新失败：回滚文件后尝试重新加载旧宠物；仍失败时保留备份路径并给出可操作提示。

## 安全边界

- Worker 只代理商店目录白名单中的资源，不能作为任意私有仓库文件代理。
- 客户端不信任 Worker 或目录中的路径、大小和摘要，必须再次校验。
- ZIP 继续拒绝路径穿越、绝对路径、符号链接、重复折叠路径、可执行文件、异常压缩比、超量文件和超限解压体积。
- 封面和预览必须由图像解码器完整解码，并限制像素尺寸，防止伪装文件和解码内存膨胀。
- 所有安装写入必须位于配置的 `pets_root`，不能由目录字段指定任意目标路径。

## 测试策略

### 资源仓库工具

- 新商品、未变化商品、ZIP 变化、仅文案变化和仅预览变化时的 `updated_at` 行为。
- 相同输入生成稳定目录，自动提取动作数、预览时间线、大小和 SHA-256。
- 拒绝非法宠物包、重复 ID、非法路径、缺失封面和不一致预览帧。

### Worker

- 商店目录、合法文件、HEAD、OPTIONS 和缓存头。
- 缺失或错误 SHA、非白名单文件、非法编码路径、目录外路径和不允许的方法。
- 商店白名单与现有资源白名单互不串用。

### 核心服务

- 目录解析和所有安全字段校验。
- 有缓存、无缓存、离线回退和损坏缓存恢复。
- 媒体按摘要缓存、ZIP 下载进度、取消、大小错误和摘要错误。
- 未领养、已领养、可更新、本地已有和目录被手工删除后的状态计算。
- 新增安装、同 ID 更新、备份、原子替换、回滚和领养记录写入时机。

### UI

- 推荐位、搜索、标签和“已领养”筛选。
- 卡片状态角标、详情返回、静态封面回退和预览播放计时。
- 底栏在未领养、下载、校验、安装、已领养和可更新状态间正确切换。
- 页面切换、关闭窗口、取消下载和资源锁定提示。
- 商店安装完成后刷新宠物库，但不自动切换当前宠物。

### 回归

- 现有导入宠物、更新宠物、宠物备份、动作导入导出、动画编辑和远程资源更新测试继续通过。
- 使用真实商店目录完成“加载首页 → 查看详情 → 领养 → 刷新后显示已领养 → 发布新 ZIP → 显示可更新 → 更新成功”的端到端流程。

## 验收标准

- 用户能在“宠物与动作”窗口中打开“宠物商店”，浏览官方精选宠物并按名称、作者或标签搜索。
- 卡片和详情页能准确区分未领养、已领养、可更新和本地已有状态。
- 详情页在不下载完整宠物包的情况下播放轻量 `idle` 预览。
- 发布者添加或更新宠物时不需要填写商店版本号；目录自动维护最后更新时间、大小和摘要。
- 领养或更新失败不会留下半个宠物包，也不会破坏现有宠物或错误写入领养记录。
- 离线时可以浏览最后一份有效缓存；无缓存时能看到明确错误和重试入口。
- 商店只负责领养与更新，不出现切换、删除或重新下载操作。
