# 重载时自动同步动作资源设计

## 背景

PetNest 当前仅加载 `pet.json` 中显式声明的动作。用户把 PNG 帧放入
`animations/sleep/` 后，即使点击“重新加载当前宠物”，该目录仍不会成为可播放
动作；系统空闲事件会因 `sleep` 未定义而回退为 `idle`。这要求普通用户手动编辑
JSON，和“目录式动作资源”的使用直觉不一致。

## 目标与范围

点击托盘的“重新加载当前宠物”时，自动发现并登记当前宠物包中尚未声明的动作目录。
同步成功后，在同一次重载中即可播放新动作，并在“编辑动画时长”中显示它。

本次不改变已登记动作的配置，也不递归扫描目录、不删除配置中已有但资源缺失的动作，
不自动创建事件绑定。

## 资源发现与写入规则

1. 扫描 `<宠物包>/animations/` 的**直接子目录**，按目录名排序。
2. 仅将含有至少一张直接 PNG 文件、且目录名尚未出现在 `animations` 配置中的目录
   视为候选动作。
3. 候选动作名称必须符合现有包校验的动作名称规则；非法名称跳过，并在结果中报告。
4. 将合格候选动作写入 `pet.json` 的 `animations`：
   - `path`：`animations/<目录名>`；
   - `fps`：10；
   - `priority`：20；
   - 除 `wake` 外，`loop`：`true`；
   - `wake`：`loop` 为 `false`，`next` 为 `context`，使其播放一次后恢复当前正常状态
     （例如 `idle` 或 `hover`）。
5. 写入前使用现有包校验器验证候选配置；校验失败时不写入、不影响当前正在播放的宠物。
6. 没有新动作时不改写 `pet.json`，保留现有“重新加载”的行为。

## 用户界面与反馈

“重新加载当前宠物”仍是唯一入口，不额外添加菜单项。同步后：

- 没有新动作：沿用现有重载成功提示；
- 有新动作：提示“已自动登记：sleep（6 帧）”等名称和帧数；
- 有非法或无法读取的目录：重载可继续完成，但提示被跳过的目录及原因；
- 配置无法安全写入或写入后的校验失败：显示错误，保持旧包和旧动画继续运行。

## 数据流

```text
托盘“重新加载当前宠物”
  -> 扫描 animations/*/
  -> 生成缺失动作定义
  -> 原子写入并校验 pet.json
  -> PackageLoader 重新读取包
  -> 应用本机动画时长覆盖
  -> PetWindow 加载新包
```

用户配置中的“动画时长覆盖”保持按宠物 ID 与动作名存储；新登记动作无覆盖时使用
`pet.json` 默认 FPS，之后用户可以在现有动画时长窗口单独调整。

## 测试

- 有 `sleep/*.png` 而 `pet.json` 未声明时，同步后生成循环 `sleep` 动作，且加载器可读到它；
- 新增 `wake/*.png` 时生成单次、`next=context` 的动作；
- 已声明动作不会被覆盖；
- 空目录、非 PNG 目录不生成动作也不改写配置；
- 非法目录名或候选配置校验失败不会破坏原 `pet.json`；
- 应用重载会加载自动登记后的动作，并向用户反馈新增动作和帧数。

## 验收标准

将 `001.png` 至 `006.png` 放入当前宠物的 `animations/sleep/`，无需手动编辑 JSON，
点击“重新加载当前宠物”后，`sleep` 会出现在动画时长编辑窗口；启用系统空闲监测并达到
睡眠阈值时，桌宠会循环播放该动作。将帧放入 `animations/wake/` 后重载，恢复电脑操作时
该动作只播放一次并恢复正常动作。
