# 次日上班边界清理设计

## 目标

仍可能触发提醒的 `prompting` 或 `overtime` 状态可以跨过午夜继续存在，但不得越过次日班次开始时间，避免昨天的加班状态覆盖今天的正常倒计时。已经结束且不会触发提醒的 `finished` 状态可以提前清理。

## 边界定义

- 固定排班以次日 `work_start_time` 为清理边界。
- 弹性排班以次日 `clock_in_start_time` 为清理边界。
- 边界通常取状态所属工作日的下一个日历日，不因次日是休息日而顺延。
- 如果弹性班次的预计结束时刻晚于该边界，则使用预计结束之后第一次到达的班次开始时间，不能在班次尚未结束时清理。
- 当前时间严格早于边界时保留旧状态；等于或晚于边界时先清除旧状态，再执行当天正常刷新。
- 弹性历史打卡本身也使用同一边界判断，不依赖是否已经存在下班状态。达到边界时清除并持久化属于旧工作日的打卡记录，防止刷新时重新生成旧状态；不得覆盖已经属于更新日期的打卡记录。
- 同一天的状态处理、30 分钟提示超时和整小时加班提醒逻辑保持不变。

## 验证

- 固定排班：边界前一秒保留，边界整点清除并显示当天倒计时。
- 弹性排班：边界前一秒保留，边界整点清除并进入当天打卡流程。
- 跨午夜弹性排班：预计结束晚于次日开始时间时，不得提前清除。
- 弹性状态清除后：旧打卡不得在同一次刷新中重建状态。
- 仅存在旧打卡而没有下班状态时：到达边界也不得自动新建昨日提醒。
- 休息日：边界整点清除并显示休息状态。
