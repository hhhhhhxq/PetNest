# 通用互动道具运行时设计

## 状态

设计已于 2026-08-30 获得确认。本规格只覆盖本版的通用运行时和宠物包可选道具；面向普通用户的可视化道具编辑器留到下一版本。平安仅作为本地验收样例，其配置和资源保持 Git 排除，不属于产品代码或发布内容。

## 背景与目标

平安已有 `litter_box`、`eat_treat`、`drink_water`、`eat_food` 四组未绑定动作。PetNest 需要提供一种有趣、可发现、且不与现有宠物拖动冲突的触发方式，同时不能把“猫条”“饭”“水”“猫砂盆”固化成系统级动作或事件分类。

本设计的目标是：

- 用户从独立道具盒拖出一个道具并投放到宠物身上，从而触发该宠物绑定的任意动作。
- 系统只定义“道具被投放”这一通用交互，不定义食物、饮水、如厕等业务语义。
- 道具的 ID、名称、图标和动作绑定均由宠物配置提供；同一外观可以绑定任意动作。
- 没有配置道具的旧宠物保持当前行为，不显示无效入口，也不要求补充资源。
- 本版建立稳定的数据模型和运行时边界，使下一版可视化编辑器可以直接复用，不需要改写事件协议。

## 不在本版范围

- 用户在设置中心新建、删除、改名、换图标、排序或重新绑定道具。
- 道具库存、消耗数量、冷却、成长值、饥饿值或每日任务。
- 道具类别、食物类型、宠物属性匹配或固定语义槽位。
- 长按宠物、双击宠物或从操作系统拖入任意文件作为道具。
- 跨设备同步用户自定义道具。

## 交互设计

### 入口

当鼠标位于宠物的非透明区域，并且当前宠物至少有一个可解析道具时，在宠物旁显示一个小型“道具盒”按钮。按钮属于独立交互控件，不属于宠物精灵的按压区域。

点击按钮后，在宠物旁展开轻量道具盘。道具盘最多同时展示八个道具；本版平安展示四个。点击空白区域、按 `Esc`、切换宠物、重新加载宠物或关闭鼠标交互时，道具盘关闭。

右键菜单同时提供“打开道具盒”入口，调用同一个道具盘，作为悬停按钮的备用入口。当前宠物没有可解析道具时，悬停按钮和右键入口都不显示。

### 道具拖放

用户从道具盘中的图标按下并移动时，拖动的是道具图标的半透明副本，宠物窗口本身保持不动。该手势的起点位于道具盘，因此不会进入现有的宠物拖动判定。

拖动副本进入宠物的非透明命中区域后，宠物显示轻量命中反馈；离开后反馈立即消失。在命中区域松开时，道具控制器生成该道具的运行时事件；在其他位置松开、按 `Esc` 或道具盘被关闭时，本次拖放取消，不产生宠物事件。

事件被状态机接受后，道具盘关闭并播放绑定动作。动作完成后沿用现有 `next: "context"` 行为，恢复悬停、工作、空闲等当前上下文。若状态机因不可中断的高优先级动作拒绝切换，道具副本回到道具盘，并给出一次轻量拒绝反馈，不排队触发。

### 与现有交互的关系

- 从宠物身体按下并移动：继续拖动宠物。
- 从道具盘图标按下并移动：只拖动道具副本。
- 单击、悬停、右键菜单和倒计时卡片维持现有语义。
- 不使用长按，因此不存在“用户停顿后才开始拖宠物却意外打开道具盘”的仲裁问题。
- 鼠标穿透、跟随鼠标或其他关闭宠物鼠标交互的模式下，道具盒入口与已打开的道具盘一并隐藏。

## 数据模型

### 宠物包声明

`pet.json` 增加可选的顶层 `interaction_items` 数组。省略该字段等价于没有道具。

```json
{
  "interaction_items": [
    {
      "id": "item_1",
      "label": "猫条",
      "icon": "items/item_1.png"
    },
    {
      "id": "item_2",
      "label": "水碗",
      "icon": "items/item_2.png"
    }
  ],
  "bindings": {
    "interaction.item.item_1": "eat_treat",
    "interaction.item.item_2": "drink_water"
  }
}
```

每条道具定义只负责展示身份：

- `id`：宠物包内稳定且唯一的无语义标识；只允许小写字母、数字、下划线和连字符，长度为 1–64。
- `label`：用户可见名称，去除首尾空白后长度为 1–40。
- `icon`：宠物包内相对路径，指向 RGBA PNG；必须通过现有包路径逃逸检查，解码尺寸不得超过 `512 × 512`。

本版每个宠物最多声明八个道具。数组顺序就是道具盘顺序，不增加单独的排序字段。

### 通用事件

运行时根据道具 ID 确定性地产生事件：

```text
interaction.item.<item_id>
```

事件前缀只表示“某个道具被投放到宠物”，不表达道具类别或预期动作。动作仍由现有 `bindings` 映射决定。例如，标签为“猫条”的道具可以绑定 `eat_treat`、`happy`、`refuse` 或任何其他可用动作。

事件使用现有状态机、优先级、不可中断规则和 fallback 解析，不建立第二套动作播放器。事件 payload 可包含 `item_id` 供诊断与未来扩展使用，但动作选择只依赖确定性的事件名与 `bindings`，不要求状态机增加 payload 条件表达式。

### 有效道具解析

只有同时满足以下条件的道具才进入运行时道具盘：

1. 道具定义通过 ID、标签、图标路径和图片校验。
2. `bindings` 中存在对应的 `interaction.item.<id>`。
3. 绑定目标可直接命中当前宠物动作，或通过现有 fallback 解析到有效的 `scope == "pet"` 动作。

无绑定、绑定目标不可解析、仅能解析到全屏动作或图标损坏的条目被跳过。其他有效条目继续可用；全部条目无效时，当前宠物等同于没有道具。

## 本地验收示例（不纳入仓库）

本地平安宠物可配置四个道具用于验收。其 ID 仅用于包内稳定引用，不成为 PetNest 的标准分类：

| 顺序 | 显示名称 | 包内 ID | 默认绑定动作 |
| --- | --- | --- | --- |
| 1 | 猫条 | `item_1` | `eat_treat` |
| 2 | 饭碗 | `item_2` | `eat_food` |
| 3 | 水碗 | `item_3` | `drink_water` |
| 4 | 猫砂盆 | `item_4` | `litter_box` |

四个动作均作为普通宠物范围的一次性动作声明，默认不可中断，播放完成后恢复上下文。动作资源本身的目录名称不构成系统事件名称，其他宠物不需要提供同名动作。

道具图标只存放在本地平安宠物包的 `items/` 中，不写入应用全局道具分类，也不跟踪到 Git。未来用户修改某个道具的名称、图标或绑定时，仍可复用同一套通用运行时。

## 组件与职责

### `InteractionItemDefinition`

不可变数据模型，保存 `id`、`label` 和已解析图标路径。它不保存动作名称，避免展示内容与动作绑定耦合。

### 包校验器与加载器

校验可选 `interaction_items`，拒绝重复 ID、不安全路径、非法字段和超限图片，并把合法记录加载到 `PetPackage`。旧包不含该字段时返回空元组。

### `InteractionItemResolver`

接收宠物包道具定义、bindings、fallbacks 和动画集合，输出有序的可用道具。它是下一版用户覆盖配置的扩展边界：本版只传包内默认定义；下一版可在解析前合并用户定义，但 UI 和拖放控制器无需改变。

### 道具盒与道具盘

只负责展示已解析道具、跟随宠物位置、打开和关闭，不直接选择动作。宠物移动或屏幕可用区域变化时，道具盘重新贴靠并限制在当前屏幕可用区域内。

### 道具拖放控制器

负责创建拖动副本、查询宠物透明像素命中、展示命中反馈、处理取消，并在成功投放时发布 `interaction.item.<id>`。它不移动宠物窗口。

### 宠物窗口适配

复用现有非透明像素命中与事件处理入口，将道具事件交给现有状态机。宠物切换、重载、鼠标交互关闭和窗口关闭时，统一清理道具盘与拖动状态。

## 下一版本编辑器接口

下一版本在设置中心增加“道具与互动”页面，但继续使用相同的 `InteractionItemDefinition`、事件命名和解析器。编辑器至少支持：

- 新建道具并设置名称和图标。
- 从当前宠物的普通动作中选择绑定目标并预览。
- 修改、删除、启用、停用和拖动排序。
- 修改包内默认道具，并恢复宠物默认配置。

用户配置保存在应用数据目录，按宠物 ID 隔离，不直接修改宠物包。用户导入的图标复制到应用管理的资源目录，不长期引用任意外部绝对路径。用户配置作为 resolver 的可选覆盖源，优先于包内同 ID 默认值；本版 resolver 接口保留该输入，但不提供编辑 UI 或持久化实现。

## 错误处理与兼容性

- `interaction_items` 是可选增量字段，所有现有宠物包继续合法。
- 单条道具损坏不会使整个宠物包无法加载；校验器报告该条问题，运行时只隐藏该条。
- 道具事件未绑定或动作不可解析时不发送无效事件，也不显示该道具。
- 宠物包更新后仍以稳定 `id` 识别默认道具，为下一版用户覆盖合并提供基础。
- 动作交换和导入流程继续把未知事件名视为合法自定义绑定，不需要登记猫条、食物、饮水或猫砂盆标准事件。
- 商店和宠物列表无需把道具名称归纳为标准能力标签；最多展示“支持互动道具”这一通用能力。

## 测试与验收

### 数据层

- 旧宠物包缺少 `interaction_items` 时加载为空且行为不变。
- 合法道具按声明顺序加载，并生成正确事件名。
- 重复或非法 ID、路径逃逸、非 PNG、超限尺寸和重复条目被拒绝或隔离。
- 缺少绑定、动作缺失、fallback 可解析和全屏动作目标分别得到正确解析结果。

### 状态与交互

- 从宠物身体拖动只移动宠物，不打开道具盘。
- 从道具图标拖动只移动副本，不移动宠物。
- 透明区域不接受投放，非透明区域接受投放。
- 成功投放发布唯一的 `interaction.item.<id>`，取消拖动不发布事件。
- 一次性动作完成后恢复悬停、工作或空闲上下文。
- 不可中断动作期间投放得到拒绝反馈且不排队。
- 切换宠物、重载、关闭交互和关闭窗口会清理所有临时 UI 与拖动状态。

### 兼容与视觉验收

- 没有道具的示例宠物和其他现有宠物不显示入口，鼠标行为与本版之前一致。
- 本地平安包按顺序显示四个道具，分别触发四个绑定动作；其文件保持 Git 排除。
- 道具盒和道具盘在屏幕边缘、高 DPI 和不同宠物缩放比例下不越出可用区域。
- 道具副本、命中反馈和关闭动画不会遮挡倒计时卡片或造成透明窗口残影。

## 成功标准

- 本地平安的四个现有动作可以通过四个包内道具稳定触发，但仓库只交付通用机制。
- 系统代码和标准事件中不存在 treat、food、water、litter box 等固定道具类别。
- 其他宠物无需修改即可继续运行；有需要时可声明完全不同的道具与动作绑定。
- 下一版编辑器只需提供用户定义与覆盖配置，不需要改变本版的道具模型、事件命名或拖放运行时。
