# 图片制作动作与资源包导入双流程设计

## 目标

在不改变现有资源包导入能力的前提下，让普通用户可以直接用多张图片或一个图片文件夹，为当前宠物创建一个 PetNest 能够真实触发的动作。

不提供任意自定义动作名称。图片创建流程只列出运行时代码支持的动作语义，避免安装后没有触发入口的无效动作。

## 页面结构

“宠物与动作 → 导入动作”页顶部保留目标宠物选择，并默认选中当前正在使用的宠物。页面主体提供两个互斥模式：

- **从资源包提取动作**
- **用图片制作动作**

两种模式分别保存未完成的输入状态；来回切换不清空来源、动作选择或预览。成功安装后只清空当前模式的本次来源数据。

## 从资源包提取动作

此模式保留现有流程和格式，不改变其识别、冲突处理、绑定导入和事务回滚逻辑：

1. 选择动作分享包 ZIP、完整宠物包/文件夹或旧版下班动画包。
2. 读取来源中的动作列表。
3. 勾选需要的动作。
4. 处理替换、跳过或重命名冲突。
5. 安装并重新加载目标宠物。

识别优先级保持确定性：

1. `petnest-action-pack.json`：动作分享包。
2. `pet.json`：完整宠物包，仅提取所选动作。
3. `manifest.json`：旧版下班动画包。

存在格式清单但清单损坏时直接报告资源包错误，不降级为普通图片导入。同时出现多个互斥清单时拒绝识别。

## 用图片制作动作

此模式一次只创建或替换一个已选定动作，操作顺序为：

1. 选择目标宠物。
2. 选择可触发动作。
3. 添加多张图片或选择图片文件夹。
4. 检查帧、调整顺序和播放速度。
5. 预览新动作；已存在时同时展示当前动作。
6. 确认替换或安装。

### 图片来源

- 支持多选 PNG、WebP，也支持拖入多张图片。
- 支持选择一个图片文件夹，只读取根目录直接包含的图片。
- 按自然顺序排列，例如 `1.png、2.png、10.png`。
- 不递归读取子文件夹；发现子文件夹时明确提示用户选择具体动作文件夹。
- 选中含资源包清单的文件夹时，提示切换到“从资源包提取动作”。
- 单张图片按单帧动作处理，不自动猜测为精灵图。
- 不提供一级子文件夹批量映射；本流程始终对应一个已选动作。

### 动作槽位

建立统一的“可触发动作表”，由运行时代码、时长编辑器和图片导入页共同使用，避免多处手工列表逐渐不一致。

动作按用户可理解的触发时机分组：

- 基础：默认待机。
- 鼠标：移入、点击、拖动、结束拖动。
- 移动：跟随鼠标移动及运行时支持的方向动作。
- Codex：任务进行中、等待处理、任务完成、执行失败。
- 系统空闲：无聊、睡觉、唤醒。
- 下班提醒：进入画面、躺下过渡、躺下循环。

内部兼容别名和旧版名称不单独暴露。选择的是动作语义，而不是固定内部名称：

- 当前宠物已有事件绑定时，替换该绑定实际指向的动作，例如 `agent.success` 可指向 `review` 或 `success`。
- 当前宠物没有对应绑定时，创建标准动作名并补充必要绑定。
- 由运行时直接按标准名称使用的动作采用其标准名称。

不提供重命名或任意自定义动作名。目标动作已存在时仅允许替换或取消。

### 动作默认值

每个动作槽位提供由触发语义决定的默认配置：

- 持续状态默认循环，例如待机、拖动、任务进行中和等待处理。
- 瞬时状态默认播放一次并返回当前上下文，例如点击、结束拖动、任务完成和执行失败。
- 下班提醒动作使用其既有全屏 scope、循环和过渡规则。
- 普通用户只调整帧顺序、播放速度或总时长；优先级、`interruptible`、`next` 等内部字段由动作槽位生成。

## 图片与画布处理

普通桌宠动作以目标宠物画布为准：

- 与画布尺寸相同的图片直接使用。
- 小于画布的图片不缩放，透明居中补齐。
- 大于画布的图片不静默裁剪；预览页要求用户选择等比缩小以适应，或返回更换图片。
- 不同尺寸的帧统一输出到目标画布，避免播放时窗口尺寸跳动。
- 原始文件不修改，输出统一为 RGBA PNG。

全屏下班动作采用独立全屏画布规则，不使用普通宠物画布。首次创建的全屏动作以本次图片最大尺寸建立画布；后续 `work_finish_walk`、`work_finish_lie_down` 和 `work_finish_lie_loop` 复用当前宠物已有的下班动作画布，避免阶段切换时尺寸跳动。预览区按统一全屏画布比例展示处理结果；`work_finish_walk` 可选择从左、从右或原地显示。

`work_finish_walk` 与 `work_finish_lie_down` 必须同时存在才启用专用全屏下班动画，缺少任一项时运行时安全回退到普通动作。选择三个下班动作槽位时显示此配套要求；`work_finish_lie_loop` 在前两项齐全时，于躺下过渡播放完成后循环。

## 预览与交互

图片模式包含：

- “添加多张图片”和“选择图片文件夹”两个明确按钮，以及拖放区域。
- 帧缩略图列表，可拖动排序、删除单帧和继续添加。
- 动画实时预览。
- 播放速度和总时长控制。
- 已存在动作时的新旧动画对比。
- 明确的“替换动作”或“安装动作”主按钮。

更换目标宠物后重新计算画布，并要求重新确认预览。安装过程中依次显示“正在处理图片”“正在安装”“正在重新加载”。成功后清空图片来源、帧列表和预览，并保留成功结果；失败时保留全部输入和排序，允许修正后重试。

## 错误与安全边界

- 损坏图片、无法解码、尺寸过大、子文件夹、符号链接或 junction 在对应来源/帧上显示具体错误。
- 设置帧数量、单图尺寸和总解码像素上限，避免异常素材耗尽内存。
- 不跟随符号链接，不写入目标宠物目录之外。
- 图片处理先在独立候选目录完成并校验。
- 动作目录和 `pet.json` 作为一个事务提交；任何复制、替换、校验或运行时重载失败都恢复原动作与配置。
- 当前宠物被全屏提醒等流程锁定时禁止安装，并说明原因。

## 验收与测试

- 原有动作分享包、完整宠物包和旧版下班动画包导入回归通过。
- 两种模式名称为“从资源包提取动作 / 用图片制作动作”，切换时各自状态不丢失。
- 默认选中当前宠物。
- 多选图片、文件夹读取、自然排序、拖动排序和单帧删除正确。
- 资源包目录不会被图片模式误识别，损坏清单不会降级。
- 图片补画布、RGBA 转换、超大图片确认和全屏画布规则正确。
- 动作语义解析当前绑定名称；缺失绑定时创建标准动作并补绑定。
- 循环、瞬时返回和全屏动作默认配置正确。
- 已存在动作只能替换或取消，不出现任意自定义名称。
- 处理、安装、重新加载状态可见；成功清空，失败保留输入。
- 安装失败后动作目录与 `pet.json` 完整恢复。
