# Windows 更新器自占用热修设计

## 问题

PetNest 0.1.2 的 `PetNestUpdater.exe` 从安装目录运行。0.1.4 安装器又要覆盖同一路径，Inno Setup 的 Restart Manager 因无法关闭更新器而在静默模式下中止安装。主程序已经退出，更新器在安装失败后也不重启它，因此用户看到应用退出后没有反应。

## 设计

0.1.5 将 Windows 更新宿主改名为 `PetNestUpdateHost.exe`，安装器不再包含旧的 `PetNestUpdater.exe`。这让由 0.1.2/0.1.4 旧更新器启动的 0.1.5 安装器无需覆盖正在运行的旧文件，可以完成一次兼容迁移。

0.1.5 及之后的主程序在安装前把新更新宿主复制到下载目录，并从该临时副本运行。安装器因此可以安全替换安装目录中的宿主。更新宿主等待主程序退出、运行安装器，并在安装成功、失败或用户取消后尝试重新启动 PetNest。

## 验证

- 单元测试验证临时副本不在安装目录、内容一致且清理旧副本。
- 单元测试验证安装器返回非零状态时仍会重启 PetNest。
- 静态安装器测试验证 0.1.5 只包含 `PetNestUpdateHost.exe`，不覆盖旧 `PetNestUpdater.exe`。
- 使用现有 0.1.2 安装目录中的旧更新器启动 0.1.5 安装包，确认安装完成并自动启动 0.1.5。
