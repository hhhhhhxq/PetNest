# Codex 用量入口解锁设计

## 目标

新用户默认看不到系统托盘中的“Codex 用量…”入口。用户在设置中心的“应用与更新”页面连续点击当前版本号 7 次后，入口立即显示，并在后续升级或重新安装 PetNest 后继续可见。

## 交互

- 每次打开设置中心时，版本号点击计数从 0 开始。
- 点击当前版本号 7 次后完成解锁；本次窗口内的计数不要求时间限制。
- 关闭设置中心而未解锁时，点击计数丢弃，不跨窗口累计。
- 解锁成功时显示一次“Codex 用量入口已解锁”的提示，并立即显示托盘入口。
- 已解锁用户再次点击版本号不会撤销或重复提示。

## 持久化与兼容

- 在 `Settings` 中新增布尔字段 `codex_usage_unlocked`，默认值为 `false`。
- 设置 schema 从 20 升至 21；旧配置迁移时补入 `false`。
- 解锁成功由应用层立即更新并保存设置，不依赖用户点击“应用并关闭”。
- 设置继续保存在系统用户配置目录中的 `settings.json`，因此覆盖安装、升级和普通卸载重装不会清除此值；用户手动删除应用数据目录时会恢复默认隐藏。

## 组件职责

- `SettingsCenterDialog`：统计版本号点击次数，达到 7 次后触发一次解锁回调并显示提示。
- `PetNestApplication`：接收解锁事件，更新 `Settings`、原子保存配置并刷新托盘入口可见性。
- `PetTrayIcon`：根据解锁状态控制“Codex 用量…”动作是否可见，并提供运行时刷新方法。
- `SettingsManager`：负责 schema 20 到 21 的默认值迁移。

## 测试

- 新用户的托盘 Codex 入口默认隐藏，已解锁用户可见。
- 版本号前 6 次点击不解锁，第 7 次只触发一次解锁。
- 关闭并重新创建未解锁设置窗口后点击计数重新开始。
- 解锁值可保存、重载，并能从 schema 20 安全迁移。
- 应用层解锁后立即保存设置并刷新托盘动作。
