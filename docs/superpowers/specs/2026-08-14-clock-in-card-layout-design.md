# 打卡卡片紧凑尺寸与屏幕避让设计

## 目标

修复部分 Windows 电脑上打卡卡片被放大到接近整屏的问题，并保证卡片随宠物移动时始终尽量完整可见、尽量不遮挡宠物。

本次只调整弹出的打卡卡片，不改变宠物倒计时气泡尺寸、打卡时间规则或用户设置格式。

## 尺寸规则

- 卡片每次显示前都重新激活布局，并根据当前字体、系统缩放和控件内容计算紧凑尺寸。
- 卡片使用计算后的固定尺寸，避免顶层无边框窗口被 Windows 或 Qt 样式意外拉伸。
- 尺寸计算使用 Qt 的设备无关坐标，不手动乘除 DPI 比例。
- 自然尺寸超过当前屏幕可用范围时，宽高限制在屏幕安全区域内；提示文字允许换行，优先保证时间框和“上工”按钮可操作。
- 卡片从其他 DPI 的显示器移入时重新计算，而不是沿用旧屏幕尺寸。

## 定位规则

以宠物中心点所在显示器的 `availableGeometry()` 为边界，避开任务栏等系统保留区域，并在边缘保留少量安全间距。

完整容纳卡片且不与宠物相交时，按以下稳定顺序选择位置：

1. 宠物右侧，垂直居中；
2. 宠物左侧，垂直居中；
3. 宠物下方，水平居中；
4. 宠物上方，水平居中。

每个候选位置都会收敛到当前屏幕安全区域，但只有收敛后仍不遮挡宠物且卡片完整可见时才算可用。

如果四个方向都无法完整放置，选择“卡片完整可见且与宠物重叠面积最小”的位置；重叠面积相同时保持右、左、下、上的优先顺序。这个降级只用于极小屏幕、超大系统字体或宠物占据大部分屏幕的情况。

## 数据流与职责

- 新增纯定位函数：输入宠物矩形、卡片尺寸、屏幕可用矩形和间距，输出卡片左上角坐标。
- `ClockInCard` 只负责根据内容和当前屏幕收紧自身尺寸。
- `WorkCountdownWindow` 负责选择宠物所在屏幕、先收紧卡片、再计算位置、最后显示。
- 宠物移动、跨屏或打卡卡片每秒刷新时都会重新检查尺寸和位置。

## 边界情况

- 宠物靠右：卡片翻到左侧。
- 左右空间不足：优先下方，其次上方。
- 宠物靠近任务栏或屏幕底部：不会把卡片放进任务栏区域。
- 多显示器缩放比例不同：使用宠物当前所在屏幕的逻辑坐标与可用区域。
- 宠物部分跨屏：以宠物中心点所在屏幕为准。
- 屏幕比卡片自然尺寸更小：卡片限制在安全区域内，并以可操作性优先。
- 四向均不足：允许最小必要重叠，但不允许卡片超出屏幕可用区域。

## 测试

- 强制把卡片放大后，再次显示会恢复紧凑尺寸。
- 卡片尺寸不超过给定屏幕安全区域。
- 宠物靠右时选择左侧。
- 左右不足且下方可用时选择下方。
- 下方不足且上方可用时选择上方。
- 正常空间充足时保持右侧优先。
- 四向均不足时卡片仍完整可见，并选择重叠面积最小的位置。
- 现有打卡时间、跨午夜和隐藏联动测试继续通过。
